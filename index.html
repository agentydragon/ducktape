01 / Where time goes

Typical feedback and background cost are different problems.

Target the gate that finishes last. A large consumer of runner time is not necessarily delaying the result the author needs.

The September diagnosis has changed. CodeQL contributed no runner time in this window. Default setup is disabled; advanced setup runs nightly/on demand. Pre-commit already cancels superseded work. These are implemented changes, not new recommendations.
02 / Recommended order

Concrete changes, with evidence and experiment limits.

Start with the tested parse-once fixture, then shallow checkout and conditional Ansible setup. The proposals name the code to change and the behavior to preserve; experiment results below separate compatibility evidence from measured performance.

01 · SPIKED, ALL TESTS PASS

Parse generated YAML once per test module.

In test_generate_manifests.py, introduce a module-scoped yaml_documents fixture keyed by file path. Have the four consumers reuse those parsed documents, preserving their different globs, parked-file filters and assertions.

Spike passed all 8 tests. cProfile attributed 36.6s to repeated YAML loading in the baseline, versus 9.5s with the shared fixture. This removes duplicate parsing without reducing validation.

36.6s → 9.5s profiled parsingOne profiled comparison; retains parsed documents in memory until module teardown

Evidence: baseline and spike. Target wall time was 101.9s → 71.7s, but generation time also varied. Measure an unprofiled comparison when implementing; 30s is not a promised production saving.

02 · CHECKOUT SPIKE PASSED

Fetch two Git generations, not the entire history.

Change fetch-depth: 0 to 2 in nix-wheel-check.yml; evaluate the same change in bazel-ci.yml. Keep the exact source ref and parent verification. The measured documentation PR spent 38s in the wheel job’s checkout.

Spike passed: fetching its exact merge commit at depth two retained both parents, passed the existing verify-source command, and produced the correct one-file diff.

At most 32s overall in this example146s wheel gate − 114s next gate; actual saving unmeasured

Before landing: run the whole wheel gate with the shallow checkout for same-repo and trusted-fork PRs and a push. The spike did not exercise Nix, artifact builds or remote handoff. Fetch additional history only if a demonstrated consumer needs it.

03 · UNNECESSARY SETUP

Install Ansible roles only when the hook will run.

In pre-commit.yml, move changed-file detection before Galaxy setup. On PRs, condition role-cache restore, role installation and cache save on changes under ansible/ or to hook configuration. This conservatively covers ansible-syntax-check; keep full setup for all-file runs and unknown selection results.

Selection confirmed: the hook skips the documentation example’s STYLE.md, yet the workflow installs Galaxy roles unconditionally. Keep running all applicable pre-commit checks.

Runner saving not yet measuredSmall workflow change; cannot shorten a 146s wheel gate by itself

Before landing: exercise documentation-only, matching playbook, hook-configuration and all-file runs. Test the gate against the hook’s actual matcher; every selected Ansible syntax check must have roles installed.

Recovery investigation: no evidence for larger timeouts, more retries, or a blanket mirror change

The 20–27 minute gaps are not attributed to a CI mechanism. Attempt-specific GitHub records identify agentydragon as the rerun account for both cases, but expose neither UI/API initiation nor the reason for the delay. We cannot claim those minutes are removable by a CI configuration change.

Browser timeout: examined all available shard diagnostics

The failed invocation has two timed-out shards at 301.5s; the other two passed. Retrieved all four test logs, the failed shards’ JUnit XML, and their Electric, PostgreSQL and ingress logs. The quiet test logs end after five and one progress dots. JUnit contains only shard-level timeout errors. Service logs show replication starting; two stream requests returned 503 among successful responses, without identifying the active test or proving causation. The in-progress test’s teardown did not produce a HAR or trace.

Concrete diagnostic change: record the active case in an undeclared-output file before executing it, enable verbose test names, and arm faulthandler.dump_traceback_later before the shard’s existing deadline. An isolated RBE spike passed: a deliberately blocked case wrote its identity and a timed stack dump, checked before teardown. This proves early diagnostic capture, not recovery of the historical root cause; it did not simulate a Bazel kill or preserve a browser HAR. It is not a demonstrated latency improvement, and the current evidence does not justify increasing the timeout.

Remote transport retries and the PostgreSQL mirror

The browser rerun automatically retried three transport errors and succeeded. That establishes neither retry-budget exhaustion nor the service-side cause; adding retries is unsupported. Read-only HEAD checks found the exact PostgreSQL layer at both the mirror and Docker Hub (HTTP 200). Switching all pulls upstream would risk the rate limits the mirror was introduced to avoid. Current availability cannot reconstruct the mirror’s historical state.

These are results of the completed artifact investigation, with a specific diagnostic boundary. The report does not count unassigned waiting time or transient failures as promised optimization savings.

Next: reduce publishing cost; measure reuse before changing capacity

Make visual announcements and no-artifact publication cheap

Visual publication used 264.4 runner-minutes. Announcement and publication run even when no visual manifest is available. For the announcement job, replace the Bazel-launched CLI with GitHub check-run API calls that retain its existing external-ID upsert behavior. This would avoid checkout/Nix/Bazel startup for a status update. For publication, a trusted preflight that enumerates the linked invocation’s actual visual manifests could avoid S3/publisher setup when none exist; missing linkage must remain an unknown result, not proof of no artifacts. Savings have not been measured; required-check savings could be zero under low contention. Preserve cancellation handling, terminal statuses, fork trust, cached visual results and real artifact uploads.

The two visual jobs also run SOPS setup while their consumed credentials are supplied directly. Remove that action from the two jobs after checking its exported values have no consumer; keep the explicitly supplied BuildBuddy, GitHub and S3 credentials. These publishing changes were source-reviewed, but no privileged publication was triggered as an experiment. The full 264.4 minutes is an upper bound on the workflow’s total cost—not an estimate of unnecessary work.

Use the existing runner probes before repinning or adding capacity

A reused outer workspace and a newly booted devel sweep were observed. They are different workloads, and neither proves an analysis-cache regression. Compare matched workloads and probe records before changing recycling, VM shape or snapshot namespace. More GitHub capacity cannot remove a serial test or an operator/recovery gap.

Required policy and agent-visible feedback: what is unmeasured

The live devel ruleset requires Gazelle diff, Build artifacts + imports check, Pre-commit checks, and bazel-ci / Test & Build. Required review count is zero; code-owner approval, last-push approval and thread resolution are not required. Strict up-to-date checking is off. No deployment or merge-queue rule appeared in the returned rules. The legacy protection endpoint returned 404; rulesets supplied the requirements.

Auto-merge being allowed, being enabled on a PR, conflicts, draft state and GitHub’s mergeability calculation are separate. Synthetic merge commits are tested while checks are attached to PR heads. Trusted forks add resolve/trust work and a bridge from the prefixed wheel job to its exact required context. Untrusted-fork environment approval is not represented well enough here to estimate its latency.

Exact push-to-auto-merge readiness, first result/log availability, and agent delivery p50/p90 are unavailable (n=0). PR #8934’s checks finished at 08:29:44, but it merged at 09:12:34. Those 42m50s are unallocated policy/operator time, not CI delay.

Notification webhooks are durably accepted before asynchronous subscription matching. Default CI subscriptions cover completed check_run and status events; App installation, fork access and delivery health determine coverage. Inbox entries do not expose acceptance/matching timestamps, and a subscription does not automatically wake a stopped harness. No inbox or raw webhook data was accessed or published.

GitHub metadata has second resolution; profile/log clocks are finer but skew was not independently measured. Remote logs were visibly batched. A future bounded observer could record head change, first queryable result/log, receipt, inbox insertion and consumer read separately—only if that evidence changes a decision. The busy window is October 4 19:45–21:15 UTC; collection ran 21:20:29–21:22:32. It includes 658 newly created workflows plus 31 active-run discoveries, some stale or after-window: 689 runs / 1432 job records across attempts. Duration percentiles filter job creation in-window, require an assigned runner, and exclude unfinished duration samples. Occupancy clips completed assigned intervals to the window.

The lower-bound total is 943.25 runner-minutes, average 10.48 runners, peak 20. Five one-minute samples reach 20 occupied runners; two include queued Bazel work.

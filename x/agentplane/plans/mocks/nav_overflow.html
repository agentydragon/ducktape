Behavior notes

  • The menu opens downward — the nav sits at the top of the viewport, the reverse of the composer bar's kebab menu, which had to open upward for the opposite reason. Mantine's default Menu placement already fits without an explicit position override.
  • "More" shows the active/filled treatment whenever the current route is one of the three menu items, not just on click — the same location.pathname === "..." check the primary buttons already use, matched against all three hidden routes at once. Landing directly on /connections (a bookmark, a link) must not look like nothing in the nav is selected.
  • Each menu item is a one-shot navigation (unlike the composer bar's "Raw frames" toggle) — Mantine's default closeOnItemClick (true) is correct here, no override needed.
  • The current menu item gets a highlighted row inside the dropdown too (not just the trigger) — opening "More" while on Connections should make it obvious which of the three you're already on.

Inside a sandbox or session — no separate nav row

Today the five-button nav renders unconditionally above every route, including a sandbox or session — so drilling in stacks the global nav row on top of that page's own back-button header, two rows of chrome doing overlapping jobs right where space is tightest. Proposed: once drilled in, the global nav row disappears entirely. The page's own back button is the way up one level; the handful of times you'd want to jump straight to Actions or Connections from deep in a session live behind a small trailing menu on that same header row instead of a whole extra row.

Behavior notes — drilled-in header

  • This is a second, distinct menu from the composer bar's own "More" shown in the composer-bar mock. That one is scoped to this session (raw frames, shut down harness); this one is global site navigation. They look alike on purpose — same kebab icon, same dropdown — but hold unrelated things, and a session page legitimately shows both: this one in the header, the session-scoped one down in the composer bar.
  • The menu's contents are a simple rule, not a hand-picked list per page: all five top-level destinations, minus whichever one the local back button already goes to. No per-route configuration to maintain as pages are added.
  • No "current route" highlighting needed here — unlike the top nav's own overflow menu, none of the five items can ever be the page you're already on while drilled into a sandbox or session.
  • Existing sandbox-page controls (state badge, Suspend/Resume, Delete) are unchanged — this only adds the trailing menu button after them, it doesn't touch what's already there.

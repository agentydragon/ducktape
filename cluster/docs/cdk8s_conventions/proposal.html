Ducktape cdk8s Conventions

Nine conventions to replace the 41 mechanism combinations that the generator's 199 shared helpers use today. Each was chosen against the jobs the cluster does often or will need soon, checked against what cdk8s can and cannot do from Python, and aligned with the move to admission-only Flux dependencies.

01The answer

Make the ducktape layer a thin layer of policy and wiring over the generated bindings, with exactly one shape per job. Nine conventions cover every need in the matrix, and all but one reuse a mechanism the tree already has.

  • C1 Provider kinds. Under providers/, a CRD kind built more than once is a single-shot class named after the kind. Schema variants are @staticmethods that return the generated struct, so a hand-built struct always fits in the same slot.
  • C2 Policy functions. A choice this cluster makes about one kind is a function named after what it returns: flux_kustomization, cnpg.cluster, https_route.
  • C3 Composites. A group of objects that repeats is a Construct whose objects and references are attributes: MintedSecret, PrivateBucket, PostgresBackup, SettingsFile.
  • C4 References. A fact two objects must agree on (a Secret key, a Service port and its Pod labels, a database's app Secret) is a small frozen reference declared once by its producer and imported by its consumers. This is the one boundary change, and it needs your approval.
  • C5 Pod policy. pod_policy.harden() and pod_policy.place() are the only functions that amend a built object. They reach cdk8s-plus, raw and CRD-embedded pod specs through one path table.
  • C6 Fleet rules everywhere. The writer attaches them to every chart, so coverage no longer depends on an author remembering.
  • C7 Rendered directories, admission-only edges. The writer returns what it rendered, and the Flux node derives decryption and deletionPolicy: Orphan from it. A dependsOn edge exists only for what the API server needs to admit the directory's objects (a CRD, a Fail webhook, a postBuild source), a synth-time check enforces that, and wait is off unless another node's admission depends on this one. One component is one Kustomization.
  • C8 Credentials. A Credential roster entry is the only way a Secret crosses namespaces.
  • C9 Config from the consumer's model. Our binaries render from their pydantic Settings; Terraform modules take a vars model checked against variables.tf.

Following cdk8s-plus's own patterns is not an option on its own: its wrappers render their specs through Lazy, which Python cannot put into typed binding fields, and the ways the tree emulated it (JSON-patch appends, a chart-wide singleton found by construct id) are its least-liked shapes. So every object is built complete, once, and there is exactly one post-construction amendment (C5). The design-space section shows the other options on each axis and why they lost here.

None of this is a big-bang rewrite. Each convention lands as a series of small PRs you can review as rendered diffs. Pod policy, the writer and the edge check can start now. The wait default and derived Orphan are postponed, and C4 and the steps built on it wait on your decision.

ID Convention Rule
C1 Provider kind classes and struct-returning variant factories

Under providers/<crd>/, a CRD kind built at more than one site is a class named after the kind. It subclasses the cdk8s_import binding and is constructed once as Kind(scope, id, *, metadata: ApiObjectMetadata, <spec fields as same-named keywords>); None leaves a field to the operator's default.

It holds no ducktape fact (namespace, zone, cluster name) and has no method that changes it after construction: a list such as bucket access is passed whole.

A nested value whose schema has real variants gets a class named after the schema concept, whose @staticmethods return the generated struct itself, so a hand-built struct is always accepted in its place.

C2 Ducktape policy is a function per kind or value shape

A choice this cluster makes about one kind, or about one recurring value shape, is a module function in the domain module, named after what it returns: flux.flux_kustomization, cnpg.cluster, gateway.https_route, helm.helm_release, terraform.gitops_terraform, cilium.fqdn_fence, namespaces.namespace with StrEnum label choices.

  • It returns the construct or generated struct it built.
  • For objects, it takes (scope, id, *, ...).
  • It takes C4 references for anything this synth builds.
  • Its docstring states its defaults as policy.

A function that only forwards its arguments to one constructor is not written; the default goes on the constructor instead (#7461). A version the function applies is a module constant in the owning module with a # renovate: comment.

C3 Composite construct for a repeated group of objects

A shape that builds two or more objects and repeats at two or more call sites is a Construct subclass. It builds all its objects in __init__ from typed inputs, and its public attributes are the objects it built and the C4 references consumers need (access_key, generator, object_store); it never returns None or a name for the caller to rebuild. Its policy is stated in its docstring, and a keyword appears only when a second caller needs it. A composite may call cdk8s-plus's own accumulators on objects it is handed (SettingsFile.mount_into calls container.mount and container.env.add_variable).

A composite renders in the owning component's Kustomization, never in a unit of its own (#7094 rule 3).

  • PrivateBucket derives its credential Secret as <name>-s3-credentials, the spelling attic, forgejo and registry-cache already use, and takes the live name where a consumer spells it otherwise: renaming secretRef in place makes the operator mint a new key pair (decision 10). local_identity: bool places the S3Identity in the tenant or in the SeaweedFS namespace, and the grant is built under an if and is not an attribute.
  • PostgresBackup lives in cnpg_backup.py, which imports cnpg and seaweedfs.s3; in cnpg.py it would close the Bazel cycle cnpg -> seaweedfs:s3 -> seaweedfs:cluster -> seaweedfs:filer_db -> cnpg.
  • A reference is named after its concept; where a module already uses the name for a string (authentik/db.py's DATABASE = "authentik"), the reference is POSTGRES.
C4 Identity-only references, declared by the producer

A fact another object or module must agree on is a frozen-dataclass reference declared once by its producer: a module constant, or for a repeated deployment a pure function of the Environment or instance key that the chart function also calls (grocy.app.service(household)), with the instance keys in one module constant (HOUSEHOLDS). Such facts include a Secret and its keys, a Service's name, ports and Pod labels, a CNPG cluster's app Secret and rw Service, and the S3 endpoint. The producer builds its objects from the reference, and every consumer, in the same chart or another Kustomization, imports it.

Projections into each dialect are methods returning generated structs:

  • env_var, env_value, and value_from for Helm env maps;
  • container_port/service_port and their k8s_ variants;
  • url and host, and fqdn where a host is compared as a string (the egress proxy's allowlist) or read from a hostNetwork Pod;
  • egress(), the client's Cilium rule, and Pods.admit(...), the server's.

url and an HTTPRoute backendRef use the Service port; egress() and the server's rules use pod_port, because Cilium matches after socket-LB translation. A Service with several ports is several ServiceRefs sharing name and Pods. A Service built from a reference carries the reference's labels, and a ServiceMonitor selects on those. A hostNetwork server has no Cilium endpoint identity, so its reference offers no egress(), and clients use the node-entity rule.

A reference holds names and the addresses derived from them, never spec. Generic references live in secret_ref.py and service_ref.py; domain references live with their domain (cnpg.PostgresRef).

C5 Pod-template policy is two functions over one path table

Cluster pod policy is pod_policy.harden(workload) and pod_policy.place(workload, placement, *, tolerate_control_plane=False). Each is called once on a finished workload of any dialect: cdk8s-plus, k8s.Kube*, or a CRD that embeds a pod template. Each finds the pod spec through ApiObject.of and POD_SPEC_PATHS, the kind-to-path table the fleet rules also read, and patches in only what is absent, using typed k8s struct values, so a value set at construction wins.

  • harden sets RuntimeDefault seccomp on the Pod, and no privilege escalation and drop-ALL capabilities on each init and main container.
  • place sets the Placement's nodeSelector, and with tolerate_control_plane adds CONTROL_PLANE_TOLERATION and PREFER_WORKERS, so the Pod uses control-plane nodes only when workers are full. It raises on a pod spec that is already placed.
  • An unknown kind raises KeyError.

node_scheduling.py exports Placement, CONTROL_PLANE_TOLERATION (k8s.Toleration) and PREFER_WORKERS (k8s.Affinity). cnpg.cluster's affinity takes the same Placement, and Helm values and operator CRs embed the same values directly: typed k8s structs render wire-shaped inside any-typed values, while quantities there stay strings.

Per-image facts (uid and gid, a writable root, added capabilities, automountServiceAccountToken) are stated at construction. Converting a KubeServiceAccount to a cdk8s-plus ServiceAccount turns its token off (automount_token defaults to False), so the same change states automount_service_account_token on every Pod that runs as that account: True where the Pod calls the API, as tana-mcp's firebase resigner does.

These are the only ducktape functions that write JSON patches, apart from a field a typed tier-1 constructor lacks.

C6 Fleet rules run on every chart, attached by the writer

write_directory registers FleetRules on every chart it synthesizes, and so does write_charts until the last hand-written-kustomization directory converts. Chart functions no longer call add_fleet_rules: the PR that attaches the rules at the writer for a chart deletes that chart's own call, since keeping both reports every finding twice.

A rule is a pure function objects -> list[str] over rendered dicts; validations run 1+N times per synth, so a rule never mutates. Exceptions are fields of a FleetExceptions value passed at the writer call, never names matched inside a rule. The hardening rule walks pod_policy.POD_SPEC_PATHS, so the check and the fix cannot disagree about where a pod spec lives. A relation that holds by construction (C3, C4) gets no rule.

The Flux graph is checked the same way: pure rules on the kustomizations chart check CRD reachability, edge justification and gating (C7 shows their shape), and their exception table is flux.ORDERING_EXCEPTIONS, whose entries carry a reason.

C7 One component, one rendered directory, one node with admission-only edges

write_directory(root, artifact, *builders, siblings=(), components=(), config_map_generator=(), chart_kinds=(), fleet=FleetExceptions()) synthesizes a component's charts with the fleet rules attached (C6), writes kustomization.yaml from the charts' own ids, the hand-written siblings, the components and the configMapGenerator entries, and returns a frozen RenderedDirectory: the artifact, the identities of the rendered objects, whether a sibling is SOPS ciphertext, and the custom-resource kinds a HelmRelease there renders (chart_kinds), which the objects cannot show.

ObjectId, STATEFUL_KINDS, RenderedDirectory, artifact_directory(artifact) and api_objects(chart), which walks chart.node.find_all() because Chart.api_objects sees direct children only, live in flux.py, their only dispatcher. generation.write_directory imports them, so the import stays generation -> flux.

  • One component is one write_directory call and one node (#7094 rule 3). It gets a second unit only for CRDs or an operator, state not yet protected by a derived Orphan, another source or age key, independent suspend, or another cadence.
  • A node for a generated directory is name(chart, directory: RenderedDirectory, *predecessors) -> Kustomization. flux_kustomization derives sourceRef and path (and raises on an explicit path=), decryption, and deletionPolicy: Orphan whenever the directory renders a stateful (API group, kind). deletion_policy=None means derive, so a disposable cache passes MIRROR_PRUNE or DELETE, and a directory whose state lives inside a chart (a HelmRelease with persistence: loki, mimir, matrix) passes ORPHAN.
  • A predecessor is an admission prerequisite of something the directory renders: the provider of its CRD; the operator whose failurePolicy: Fail webhook gates it (ESO, CNPG, cert-manager, Kyverno, virt-api, CDI; prometheus-operator, SeaweedFS, tofu-controller and Valkey have none, so their consumers need only the CRD); or a postBuild.substituteFrom source. Any other edge is an entry in flux.ORDERING_EXCEPTIONS, whose reason is that the bootstrap never converges without it or that applying out of order destroys something (#7094 rule 2).
  • wait defaults to None (Flux: off). Only an admission target passes wait=True, or health_check_exprs where the object has no Ready condition (kubevirt, cdi; #7699); its health checks come from directory.health_checks(kinds).
  • Synth-time validations on the kustomizations chart read each node's RenderedDirectory and fail when a rendered custom-resource kind does not reach its provider in OPERATOR_CRDS, when an edge is neither admission-justified nor listed, when wait or a health check sits on a node no such edge targets, or when an admission target does not gate. They check hand-passed edges; they never choose them.
  • A value the generator knows renders in Python, never through postBuild substitution.

The entry point builds the artifact, calls the writer, then the node, and last hands every directory to the graph validation and every artifact to write_artifact_generators. Nodes never write.

C8 Secrets cross namespaces only through a Credential

A Credential(source: SecretRef, consumers: frozenset[str]) is the only authorization for a Secret to be read outside its namespace, and Credential.__post_init__ raises on an empty consumer set. SOPS sources are named constants in external_creds.py; an in-cluster source (a minted bearer, a controller output) is declared beside its producer.

  • Source side: the chart that owns the source Secret calls credentials.grant(chart, *credentials) once, because that chart owns the namespace's one store. It renders an exact-name, get-only Role per Secret, a RoleBinding per consumer namespace's external-creds-reader named <secret>-<namespace>-reader, and the namespace's one referent-auth ClusterSecretStore external-creds-<namespace>, whose namespace list is derived from the consumers. It renders in the source's existing unit, never a new one.
  • Consumer side: credentials.copy(scope, id, credential=, target=SecretRef, keys=) renders the ExternalSecret and fails synth when target.namespace is not approved. The consumer namespace's external-creds-reader ServiceAccount is created once, by the chart that creates that namespace (flux-system's by the external-creds chart).
  • Flux: a consumer's only edge for a copy is external-secrets-operator, whose failurePolicy: Fail webhook admits the ExternalSecret; ESO retries until the store exists. The external-creds node depends on external-secrets-operator, because the ClusterSecretStore CRD and webhook must exist before its store applies.

New random values are C3 MintedSecrets.
C9 Configuration renders from the consumer's own model

Configuration a program reads is rendered from a model of that program's own schema:

  • An in-repo binary: its pydantic Settings through util/settings_contract. settings_file goes into a SettingsFile ConfigMap (C3); env_name and cli_args render flags and env; secrets arrive as SecretKey projections under the Settings field's env name (#7426).
  • A Terraform module: its variables are a frozen, extra=forbid pydantic model that mirrors variables.tf, passed as gitops_terraform(variables=...). One relation test ties each model's top-level field names to variables.tf (nested object attributes stay unchecked), and the module's BUILD exports variables.tf for it. Terraform CRs group per external system (forgejo-gitops, authentik-tf, github-tf) unless a #7094 rule-3 exception applies, and order among themselves through the CR's own spec.dependsOn (gitops_terraform(depends_on=...)), never through Flux dependsOn.
  • A vendor binary keeps its own env or config mechanism, built from one dict (ntfy's NTFY_* env).

Reloader runs with autoReloadAll (reloader.py:47): a workload opts out with "false", and the 44 "true" annotations are deleted. 7 of them sit on pod templates, chart podAnnotations or operator CR templates (headlamp.py:75, gatus/app.py:107, proxmox_proxy.py:102, seaweedfs/cluster.py:380, ...), which Reloader never reads (reloader.py:39-44). The comments at haku_egress_proxy.py:266, 438 and public_coder_proxy.py:241 that credit the annotation with rolling a proxy point at autoReloadAll instead.

Principles behind them

One shape per job

Each job the layer does has exactly one mechanism, chosen from mechanisms the tree already uses. A second shape for the same job is a review finding.

Root causes 1 and 8: 199 shared helpers use 41 mechanism combinations, and each open dedup PR added one more. Choosing among shapes the tree already has keeps the learning cost and the migration diff small.

Generated bindings are the model

Objects are built from cdk8s-plus, k8s.Kube* or cdk8s_import bindings. Ducktape code adds policy and wiring on top and never adds a parallel deployment specification or IR.

The owner's first cdk8s review steered a hand-rolled spec record toward generated bindings (#7109), and PLAN.md F forbids a parallel deployment specification (cluster/cdk8s/PLAN.md:161-162).

Build complete, once

Ducktape code builds each object from complete inputs in one constructor call and does not amend it afterwards. The one exception is pod_policy.harden/place. cdk8s-plus's own accumulators are used the way upstream intends.

A Lazy in a typed Python slot raises a jsii TypeError (#8067). jsii structs are copied by value at construction, so later edits to them never reach the output. JSON-patch accumulation is the shape the owner accepts only as a required hatch (#7967).

Facts cross as references

A fact that two objects or modules must agree on is declared once, by its producer, as an identity-only reference. Each consumer projects its own half from the reference and never spells it again.

Root cause 3. It also meets the owner's 'no hand-copied strings the generated types already know' (#7969).

Derive, do not restate

Anything computable from what was built is derived in the one place that knows it: decryption, deletionPolicy: Orphan, health checks, store allowlists, RoleBinding names, kustomization file lists.

Root causes 5 and 7. The 21 missing Orphans and the store-allowlist outages both came from restated facts.

Enforce by construction, then by rule

An invariant holds by construction where it can. Where it cannot, a pure synth-time rule checks every chart the writer produces and the whole Flux graph. Nothing relies on an author opting in.

Fleet rules run on 12 of 188 charts today, and the graph check misses 16 rendered custom-resource kinds. Opt-in enforcement fails at the rate the inventory measured.

providers/ is schema, the ducktape layer is policy

providers/ holds CRD structure and its real variant shapes. Every namespace, name, zone, image or retention choice lives in a ducktape module.

The owner's layering rule (#5099), confirmed by the KEDA incident (#7952) and written down at cluster/cdk8s/AGENTS.md:302-312.

Admission, not readiness

A Flux dependsOn edge exists only where the API server would reject the dependent's objects without the target: the provider of a rendered kind's CRD, the operator whose failurePolicy: Fail webhook gates it, or a postBuild.substituteFrom source. Everything else converges by retry.

wait and health checks sit only on a node such an edge points at, and a component is one Kustomization.

Readiness edges turn a fault that heals by retry into a gate that propagates, and the tiny units they produced cost reconcile time and I/O, which is the owner's reason for the change (#7094). On devel 1faf6d5f22, 271 of 426 edges are not admission edges, 101 of the 129 wait: true nodes gate nothing admission needs, and 71 of 176 measurable units render 3 objects or fewer.

02The design space

There are many ways the ducktape layer could integrate with cdk8s. The choices fall along a few independent axes: how an object gets built, how cross-cutting policy reaches it, how facts cross between objects and modules, how two-sided relationships are wired, how output and the Flux graph are organized, and where each abstraction lives.

Each axis below lists the options that were considered, with a verdict and the reason in this repo, and names the pick. The last axis compares whole-design angles, which four independent designers each developed in full before three judges scored them. Prior art from other tools closes the section.

Object construction

How does ducktape code produce an object whose inputs are known at different points of the chart function?

Option Verdict How it works here, and why
Single-shot constructor adopt

Every input arrives in one __init__ or function call, and the object is complete when it returns. It matches the generated jsii structs, which are copied by value at construction.

cdk8s-plus fluent accumulators adopt

add_container, mount, env.add_variable, Role.allow and add_subjects render at synth whenever they are called, because cdk8s-plus renders its L1 through Lazy internally. They are used as upstream intends, including from a composite (SettingsFile.mount_into).

Python-side builder with build() reject

It needs neither Lazy nor patches (checked in a scratch environment), but anything added after build() is silently lost, and accumulating across charts needs a shared builder object, which is a registry. Passing the complete list to the constructor needs neither.

JSON-patch accumulation on a built binding reject

Bucket.grant appends raw dicts at /spec/access/- (seaweedfs/s3.py:225-231), and _ClusterGrant is a chart singleton found by construct id (s3.py:111-121). The owner accepts a patch only as a required hatch (#7967), and a /- append needs an existing list.

Synth-time rendering (Lazy, a to_json override, App resolvers) reject

Lazy raises a jsii TypeError in any typed slot (#8067) and works only in any-typed ones such as HelmRelease values. A to_json override edits wire JSON after the generated mapping, and a resolver is app-global and would have to reach 20 App( sites.

Pick

C1 and C3 build everything ducktape writes in one call, and cdk8s-plus's accumulators are used where upstream provides them (principle 3). The one amendment after construction is pod policy (C5).

How cross-cutting policy reaches objects

How does a rule that applies to many objects, such as pod hardening or placement, get onto each of them?

Option Verdict How it works here, and why
Module constants and kwargs bundles reject

WRITABLE_ROOT (container_security.py:10-14), #8115's drop-ALL constants and #8109's TypedDict spread each reach one pod dialect and hide which fields they set. Every author still has to remember to use them.

Defaults in wrapper constructors restrict

Right for policy over one kind, stated in the function's docstring (flux_kustomization, cnpg.cluster; C2). A constructor default cannot reach the 54 raw k8s.Kube* workloads or the pod specs inside SandboxTemplate and ScaledJob.

Mutator functions on a built construct restrict

pod_policy.harden and place find the pod spec through one kind-to-path table and fill only what is unset, on cdk8s-plus, raw and CRD pods alike (checked in a scratch environment with the real SandboxTemplate binding). They raise on a kind without a pod template.

Constructs mixins (with_()) reject

The same eager walk as a mutator, plus jsii IMixin ceremony. It silently skips constructs it does not support, and a chart-level call applies to every workload in the chart.

Admission-time mutation (Kyverno) restrict

Kyverno mutates Pods the generator does not author and guards admission (kyverno/policies.py:156-350). Used as the default for generated objects, it would make the snapshot and the fleet rules misstate what runs.

Validation only (fleet rules) adopt

A pure rule over rendered objects catches what a mutator missed, such as a container added after harden(). The writer attaches it to every chart, where 12 of 188 charts opt in today (C6).

Pick

C5 fills pod policy on every dialect and C6 checks the result on every chart; policy over one kind is a C2 default. Kyverno keeps the Pods the generator does not author.

How facts cross objects and modules

When two objects or two modules must agree on a name, port, label set or Secret key, what carries the fact?

Option Verdict How it works here, and why
Repeated strings reject

Today's default: ntfy's port is written 6 times in one module (ntfy.py:78 and five reuses), external-creds-reader 19 times, and -app/-rw names are derived by hand 12 times.

Module constants restrict

The only sanctioned carrier today (cluster/cdk8s/AGENTS.md:52-56). One constant holds one string, so a Service's name, port and Pod labels become three constants that each consumer recombines.

Construct references within one chart adopt

Where cdk8s-plus holds a relation by construction (Service(selector=deployment), Volume.from_config_map), the construct is the reference. It works only where both objects are built in the same synth, so it never reaches a consumer in another Kustomization.

Identity-only references adopt

A frozen dataclass of names, keys, ports and labels, declared once by the producer and projected into each dialect by methods (C4). It needs the one boundary change in cluster/cdk8s/AGENTS.md:8-13 (decision 1).

A registry or 'provides' declarations reject

cluster/cdk8s/AGENTS.md:8-13 and cluster/cdk8s/TODO.md:42 forbid it. A lookup resolved at synth hides which module a fact came from.

An intermediate app model or IR (Score, Timoni) reject

It is the parallel deployment specification PLAN.md F forbids; the proposal built on it scored 4/10 on owner fit. Its per-namespace SeaweedFS Tenant cannot be built where one namespace's buckets belong to several Kustomizations.

Pick

C4 references for anything that crosses a module or a Kustomization, construct references inside one chart, and constants only for facts that are the same everywhere.

How two-sided relationships are wired

When a relationship has two halves (client egress and server ingress, a Secret's source grant and its copy, a bucket and its identity), who builds each half?

Option Verdict How it works here, and why
Each side by hand reject

Today's network wiring: the client's URL and egress rule and the server's ingress rule are written separately from string constants, and cilium.endpoint_labels gets a string name at 31 of 39 sites.

Grant methods on a built resource (AWS CDK Grants) reject

Both halves need an accumulation point, which on typed Python bindings is a JSON patch or a chart singleton (Bucket.grant, _ClusterGrant).

A facade returning both halves reject

The caller has to take the pair apart. #8111's combinator was indexed with [1], the owner objected, and a flag was added to avoid the index.

Connections (cdk8s-plus PodConnections) reject

allow_to and allow_from write both directions from one call, but they emit networking.k8s.io NetworkPolicy, and this cluster enforces CiliumNetworkPolicy.

Two projections of one reference adopt

The producer exports a ServiceRef; the client builds url and egress(), and the server admits the client's Pods on pod_port, each in its own chart (C4). Nothing is re-spelled, and no call site needs both charts.

A roster that authorizes both sides adopt

A Credential names a Secret and its consumer namespaces once; the source's chart renders the Role, RoleBindings and store from it, and copy() refuses an unapproved consumer at synth (C8, #7455).

A composite that owns both sides adopt

Where one owner builds both halves, one construct builds them and exposes the results (PrivateBucket: bucket, identity, credentials and grant; C3).

Pick

C4 projections for network paths, the C8 roster for cross-namespace Secrets, and a C3 composite when one owner builds both halves.

Output: the writer and the Flux node

Who writes a generated directory, and how does its Flux node learn what the directory contains?

Option Verdict How it works here, and why
A node that writes its own directory reject

12 node functions take root, synthesize and write (ntfy.py:307-338), although cluster/cdk8s/AGENTS.md:111-112 says a Kustomization never builds the chart it describes.

Facts passed to each node as keywords reject

Today's join: SOPS_DECRYPTION passed by hand at 51 nodes, 42 health-check entries typed out, and 21 of 39 stateful units without deletionPolicy: Orphan.

A writer that returns what it rendered adopt

write_directory synthesizes the charts with the fleet rules attached, writes kustomization.yaml, and returns a RenderedDirectory from which the node derives source, path, decryption and Orphan (C7). PLAN.md F keeps write_charts until a composition or validation need justifies a new writer, and this meets both.

A node base class or registry (#7444) reject

cluster/cdk8s/AGENTS.md:98-101 and PLAN.md F forbid it, and a plain value returned by the writer gives the same derivation.

Hand-written kustomization glue restrict

Only what must stay YAML: image-pins Components with their Setters markers, and SOPS siblings, both listed by the writer (P18).

Pick

C7: one write_directory call per component returns a RenderedDirectory, and the node reads it. Nodes never write.

Flux graph: units and edges

How many Kustomizations does a component get, what may a dependsOn edge express, and where does wait go?

Option Verdict How it works here, and why
A unit per concern (namespace, database, secrets, bucket, provisioner) reject

It produced the tiny units: 71 of 176 measurable Kustomizations render 3 objects or fewer, and each costs its own reconcile loop and I/O.

One Kustomization per component (#7094 rule 3) adopt

A second unit only for CRDs or an operator, state not yet protected by Orphan, another source or age key, independent suspend, or another cadence. Derived Orphan (C7) makes folding stateful objects into the component safe.

Readiness edges reject

271 of 426 edges wait on runtime state: a store, a database, a Gateway, a namespace. Each turns a fault that heals by retry into a gate that propagates, with one alert per downstream node (#7094).

Admission-only edges (#7094 rule 1) adopt

An edge points at the provider of a rendered kind's CRD, an operator whose failurePolicy: Fail webhook gates it, or a postBuild.substituteFrom source; 155 of today's edges qualify. Any other edge is an ORDERING_EXCEPTIONS entry with one of two reasons.

dependsOn derived from rendered kinds reject

Choosing the predecessor from a kind makes the graph implicit and turns the kind-to-provider map into the 'provides' registry the boundaries forbid. OPERATOR_CRDS stays a map that checks hand-passed edges.

Hand-passed edges checked at synth adopt

Predecessors stay parameters (cluster/cdk8s/AGENTS.md:84-101), and validations on the kustomizations chart check CRD reachability and edge justification, which also closes the parse_cluster gap #7763 reported.

wait on every node reject

ntfy.py (338 lines) is a typical small HTTP service. It uses:

Root causes

  • No target shape per job, so each helper author chose one. 199 shared helpers use 41 mechanism combinations, and providers/ disagrees with itself:

    • 11 factory classes return a wrapper that callers unwrap with .to_spec() (39 unwrap calls, for example gateway.py:78,103 and providers/external_secrets/external_secret.py:172-174), while EgressRule, IngressRule and Endpoint return the generated struct.

    • 8 providers/ modules import the root metadata() helper, against the rule that providers/ is schema only (cluster/cdk8s/AGENTS.md:302-312).

    'One helper per repeated shape' (cluster/cdk8s/AGENTS.md:64-71) says to name a shape but not which mechanism, and its own examples mix a mutator (node_scheduling.py), a JSON patch (pod_spec_patches.py) and value factories.

  • The TypeScript cdk8s-plus idiom, where an L2 accumulates state and renders its L1 through Lazy, cannot be reproduced on typed Python bindings: a Lazy in a typed slot raises a jsii typeguard TypeError, as #8067 recorded. Helpers that wanted incremental APIs emulated it:

    The owner accepts a JSON patch only as a required hatch (#7967).

  • Producers do not export what consumers need. The boundary 'no record type standing in for an object' (cluster/cdk8s/AGENTS.md:8-13) left a bare string constant as the only sanctioned carrier for a fact that crosses modules. Results:

    • one port is written 6 times in one module (ntfy.py:78 defines it; 221, 252, 256, 269-270 and 287 reuse it);

05Pattern catalog

The design-space axes above are built from these pattern families: every shape a helper in this layer can take, from a constant to an intermediate model. Each gets a verdict: adopt it as a convention, restrict it to named cases, or reject it. The matrix below scores each family against each need.

ID Pattern Verdict Why
P1 Constant restrict

Allowed for facts that are the same everywhere: Placement values, BEARER_PASSWORD, POSTGRES_IMAGE and other # renovate: pins, exported references, a directory's SIBLINGS tuple, and the checking tables OPERATOR_CRDS and flux.ORDERING_EXCEPTIONS. Not allowed for per-app configuration (#4678) or for bundles of policy structs (WRITABLE_ROOT, #8115's drop-ALL pair, SOPS_DECRYPTION passed at call sites). Those become harden(), C2 defaults, or derivations.

P2 Value factory restrict

Only a function that derives something (cilium.fqdn_fence, RenderedDirectory.health_checks, PostgresRef.rw, cnpg.same_owner_initdb deriving the owner role from the database name) and returns a generated struct or a plain value. A function that only forwards its arguments to one constructor is not written (#7461: metadata(), _secret_env); that covers the merged env_helpers (#8113) and #8106. No factory returns a kwargs TypedDict to spread (#8109, LONG_LIVED_CA).

P3 Classmethod factories adopt

The single shape for schema variants: @staticmethods on a concept-named class that return the generated struct (EgressRule.to_entities #7969, Rule.alert #8010, Endpoint.bearer_authorization #8098). The 11 .to_spec() wrappers convert to it. Classmethods on our own frozen values (PostgresRef.generated) follow the same shape.

P4 Kind wrapper class adopt

Already the majority shape in providers/. A subclass of the binding stays an ApiObject that ApiObject.of, harden() and RenderedDirectory can see. It is single-shot, takes metadata: ApiObjectMetadata, and holds no ducktape facts.

P5 Composite construct adopt

The one shape for a repeated group of two or more objects. Its objects and references are attributes, so nothing returns None or a name (#8114's shape), and it renders in its owner's Kustomization. Limited by 'two call sites, no application base class' (PLAN.md F, #7444).

P6 Resource function adopt

Ducktape policy over one kind (flux_kustomization with about 180 calls, cnpg.cluster, https_route, helm_release, gitops_terraform), plus credentials.grant/copy and write_directory. About 290 call sites already use it, and converting them to classes buys nothing.

P7 Mutator on a built construct restrict

Exactly two: pod_policy.harden and pod_policy.place. Pod policy is the one concern that must reach cdk8s-plus, raw and CRD pod specs, and an explicit function that raises on a kind without a pod template reaches all three; this was checked in a scratch environment on a cdk8s-plus Deployment, a raw CronJob and the real SandboxTemplate binding. attract_to_zone, tolerate_control_plane_taint and apply_pod_spec_patches are deleted.

P8 Incremental methods restrict

cdk8s-plus's own accumulators are used as upstream intends: add_container, mount, env.add_variable, Role.allow, add_subjects, and SettingsFile.mount_into, which calls them. Ducktape classes do not add accumulating methods.

On a built typed binding, accumulation means JSON-patch appends or a singleton lookup (Bucket.grant, _ClusterGrant). A Python-side builder that constructs once in build() avoids both, as a scratch-environment check showed, but it adds a finalize step and silently drops anything added after build(). A complete list passed to the constructor (C1 access=, C8 consumers=) states the same thing without an ordering rule.

P9 JSON patch restrict

Only inside pod_policy (fill-if-absent, typed k8s struct values) and for a field a typed tier-1 constructor lacks (topologySpreadConstraints). Checked sharp edges: a /- append needs an existing list, a patch under an absent parent throws at synth, and a path outside the binding's schema is silently dropped. All three are too sharp for call sites.

P10 Constructs mixin reject

with_() is the same eager subtree walk as harden(). It adds jsii IMixin ceremony (a frozen dataclass cannot implement it) and silently skips constructs it does not support, where the plain function raises. A chart-level with_(Pinned(...)) would also pin every workload in the chart.

P11 Synth-time rendering reject

In Python, Lazy works only in any-typed slots: metadata.add, HelmRelease values, a CRD schema example. In a typed field it raises (#8067). cdk8s-plus still uses Lazy internally, and the layer uses its accumulators. Even in any-typed Helm values, a Lazy would make the rendered values depend on call order across the chart function, visible only in the snapshot, for values that can be computed up front.

A to_json override edits wire JSON after the generated mapping, where no reader looks, and App resolvers are app-global. One checked fact is kept for later: a JSON patch of a core PodSpec into a CRD slot is filtered by the CRD's toJson whitelist, and a to_json override is not. No need in N1-N34 requires it.

P12 Props / profile value adopt

The frozen Environment per namespace stays unchanged. Placement, FleetExceptions, Credential and the Settings and Terraform-vars models are the same kind of value: data only, never callables (cluster/cdk8s/AGENTS.md:37-42).

P13 Typed outputs and references adopt

Identity-only references declared by producers (SecretRef, SecretKey, Port, Pods, ServiceRef, PostgresRef), composite attributes, and the writer's RenderedDirectory. This is the root-cause fix for re-spelled strings, and it needs the one boundary change.

P14 Relationship facade restrict

Only the Credential roster, which declares both ends of a Secret read on the authorizing side, as the owner's external-creds standard does (#7455). A network relationship is two projections of one reference; a facade that returns a pair gets split by index (#8111). Per-pair stores built from the consumer's chart (single_secret_store, the proposed SecretCopy) are rejected.

P15 Intermediate model reject

It is the parallel deployment specification PLAN.md F forbids, and it invites field creep. Its per-namespace SeaweedFS Tenant cannot be built where one namespace's buckets belong to several Kustomizations: namespace monitoring holds separate grants for mimir and tempo. Pydantic models that mirror a consumer's own schema (Settings, variables.tf) are C9, and RenderedDirectory records what was built; neither describes what to build.

P16 Validation adopt

Pure rules over rendered objects, attached by the writer to every chart, with exceptions as FleetExceptions fields. The same mechanism checks the Flux graph on the kustomizations chart: CRD reachability, edge justification against flux.ORDERING_EXCEPTIONS, and gating only on admission targets. The hardening rule shares POD_SPEC_PATHS with harden(), so the check and the fix agree.

P17 Admission-time mutation restrict

Kyverno handles Pods the generator does not author (Helm charts, operators, agents) and serves as admission defence. It is never the source of a default for a generated object, because the snapshot and the fleet rules cannot see it.

P18 Kustomize-side composition restrict

Allowed for hand-written image-pins Components (Setters markers must be YAML), SOPS siblings and configMapGenerator entries, all listed by write_directory. No Kustomize patches or replacements over generated objects (#5068), and no postBuild substitution of a value the generator knows: LETSENCRYPT_ISSUER renders in Python.

What Python cdk8s can and cannot do (checked in a scratch venv)

  • Lazy works only in any-typed slots, such as metadata.add(...) or HelmRelease values. Put into a typed struct field, it fails jsii's type check with a TypeError, which is why #8067 was closed. The TypeScript cdk8s-plus pattern, where a wrapper renders its spec lazily from mutable state, cannot be reproduced on typed Python bindings.

  • Generated structs (k8s.*, CRD *Spec types, cdk8s-plus props) are read-only values copied into the construct at construction. Mutating one afterwards changes nothing.

  • cdk8s-plus classes are real accumulators: add_container, mount, env.add_variable, Role.allow, add_subjects and metadata labels all show up at synth when called later. Fields captured from props at construction (a container's securityContext, image, resources, probes) can only change through a JSON patch.

  • There are no Aspects in cdk8s 2.70 or constructs 10.8. The constructs IMixin and construct.with_(...) work from Python, but they are eager: they apply to the subtree as it exists at call time and silently skip constructs they don't support.

  • node.add_validation runs 1+N times per synth (N charts), so a validation must be pure. App(resolvers=[...]) works from Python but is app-global.

  • Overriding to_json() in a Python subclass of a generated binding works: cdk8s calls it at synth. It edits wire-shaped JSON after all other rendering.

  • JSON patches on typed bindings apply before the generated field mapping, so paths use the binding's property names and values should be typed structs.

  • cdk8s-plus's ServiceAccount renders automountServiceAccountToken: false by default, so converting a raw ServiceAccount silently removes the token from pods that relied on it.

07The conventions

C1

Provider kind classes and struct-returning variant factories

Under providers/<crd>/, a CRD kind built at more than one site is a class named after the kind. It subclasses the cdk8s_import binding and is constructed once as Kind(scope, id, *, metadata: ApiObjectMetadata, <spec fields as same-named keywords>); None leaves a field to the operator's default.

It holds no ducktape fact (namespace, zone, cluster name) and has no method that changes it after construction: a list such as bucket access is passed whole.

A nested value whose schema has real variants gets a class named after the schema concept, whose @staticmethods return the generated struct itself, so a hand-built struct is always accepted in its place.

C4

Identity-only references, declared by the producer

A fact another object or module must agree on is a frozen-dataclass reference declared once by its producer: a module constant, or for a repeated deployment a pure function of the Environment or instance key that the chart function also calls (grocy.app.service(household)), with the instance keys in one module constant (HOUSEHOLDS). Such facts include a Secret and its keys, a Service's name, ports and Pod labels, a CNPG cluster's app Secret and rw Service, and the S3 endpoint. The producer builds its objects from the reference, and every consumer, in the same chart or another Kustomization, imports it.

Projections into each dialect are methods returning generated structs:

  • env_var, env_value, and value_from for Helm env maps;
  • container_port/service_port and their k8s_ variants;
  • url and host, and fqdn where a host is compared as a string (the egress proxy's allowlist) or read from a hostNetwork Pod;
  • egress(), the client's Cilium rule, and Pods.admit(...), the server's.

url and an HTTPRoute backendRef use the Service port; egress() and the server's rules use pod_port, because Cilium matches after socket-LB translation. A Service with several ports is several ServiceRefs sharing name and Pods. A Service built from a reference carries the reference's labels, and a ServiceMonitor selects on those. A hostNetwork server has no Cilium endpoint identity, so its reference offers no egress(), and clients use the node-entity rule.

A reference holds names and the addresses derived from them, never spec. Generic references live in secret_ref.py and service_ref.py; domain references live with their domain (cnpg.PostgresRef).

C5

Pod-template policy is two functions over one path table

Cluster pod policy is pod_policy.harden(workload) and pod_policy.place(workload, placement, *, tolerate_control_plane=False). Each is called once on a finished workload of any dialect: cdk8s-plus, k8s.Kube*, or a CRD that embeds a pod template. Each finds the pod spec through ApiObject.of and POD_SPEC_PATHS, the kind-to-path table the fleet rules also read, and patches in only what is absent, using typed k8s struct values, so a value set at construction wins.

  • harden sets RuntimeDefault seccomp on the Pod, and no privilege escalation and drop-ALL capabilities on each init and main container.
  • place sets the Placement's nodeSelector, and with tolerate_control_plane adds CONTROL_PLANE_TOLERATION and PREFER_WORKERS, so the Pod uses control-plane nodes only when workers are full. It raises on a pod spec that is already placed.
  • An unknown kind raises KeyError.

node_scheduling.py exports Placement, CONTROL_PLANE_TOLERATION (k8s.Toleration) and PREFER_WORKERS (k8s.Affinity). cnpg.cluster's affinity takes the same Placement, and Helm values and operator CRs embed the same values directly: typed k8s structs render wire-shaped inside any-typed values, while quantities there stay strings.

Per-image facts (uid and gid, a writable root, added capabilities, automountServiceAccountToken) are stated at construction. Converting a KubeServiceAccount to a cdk8s-plus ServiceAccount turns its token off (automount_token defaults to False), so the same change states automount_service_account_token on every Pod that runs as that account: True where the Pod calls the API, as tana-mcp's firebase resigner does.

These are the only ducktape functions that write JSON patches, apart from a field a typed tier-1 constructor lacks.

    pod = obj.to_json()

def harden(workload: Construct) -> None:
    """Fills what the pod spec leaves unset: RuntimeDefault seccomp on the Pod; no privilege escalation
    and every capability dropped on each container. Call it once every container exists; the fleet
    rule names a container added later."""
    obj, path, pod = _pod_spec(workload)
    if "securityContext" not in pod:
        obj.add_json_patch(JsonPatch.add(f"{path}/securityContext", k8s.PodSecurityContext(seccomp_profile=_RUNTIME_DEFAULT)))
    elif "seccompProfile" not in pod["securityContext"]:
        obj.add_json_patch(JsonPatch.add(f"{path}/securityContext/seccompProfile", _RUNTIME_DEFAULT))
    for field in ("initContainers", "containers"):
        for index, container in enumerate(pod.get(field, [])):
            at = f"{path}/{field}/{index}/securityContext"
            context = container.get("securityContext")
            if context is None:
                obj.add_json_patch(
                    JsonPatch.add(at, k8s.SecurityContext(allow_privilege_escalation=False, capabilities=_DROP_ALL))
                )
                continue
            if "capabilities" not in context:
                obj.add_json_patch(JsonPatch.add(f"{at}/capabilities", _DROP_ALL))
            if "allowPrivilegeEscalation" not in context:
                obj.add_json_patch(JsonPatch.add(f"{at}/allowPrivilegeEscalation", False))


def place(workload: Construct, placement: Placement, *, tolerate_control_plane: bool = False) -> None:
    obj, path, pod = _pod_spec(workload)
    if "nodeSelector" in pod or "affinity" in pod:
        raise ValueError(f"{obj.kind}/{obj.name}: already placed")
    obj.add_json_patch(JsonPatch.add(f"{path}/nodeSelector", placement.node_selector))
    if tolerate_control_plane:
        obj.add_json_patch(JsonPatch.add(f"{path}/affinity", PREFER_WORKERS))
        obj.add_json_patch(
            JsonPatch.add(f"{path}/tolerations/-", CONTROL_PLANE_TOLERATION)
            if "tolerations" in pod
            else JsonPatch.add(f"{path}/tolerations", [CONTROL_PLANE_TOLERATION])
        )

Secrets cross namespaces only through a Credential

A Credential(source: SecretRef, consumers: frozenset[str]) is the only authorization for a Secret to be read outside its namespace, and Credential.__post_init__ raises on an empty consumer set. SOPS sources are named constants in external_creds.py; an in-cluster source (a minted bearer, a controller output) is declared beside its producer.

It renders in the source's existing unit, never a new one.

The external-creds node depends on external-secrets-operator, because the ClusterSecretStore CRD and webhook must exist before its store applies.

def grant(scope: Construct, *credentials: Credential) -> ClusterSecretStore:
    """Source side, called once by the chart that owns the source namespace: per Secret an exact-name
    get-only Role bound to each consumer namespace's READER, and the namespace's one referent-auth store
    admitting exactly those consumers."""
    namespace = one({credential.source.namespace for credential in credentials})
    for credential in credentials:
        source = credential.source.name
        role = Role(
            scope,
            f"{source}-reader",
            metadata=ApiObjectMetadata(name=f"{source}-reader", namespace=namespace),
            rules=[RolePolicyRule(resources=[Secret.from_secret_name(scope, f"{source}-source", source)], verbs=["get"])],
        )
        for consumer in sorted(credential.consumers):
            RoleBinding(
                scope,
                f"{source}-{consumer}",
                metadata=ApiObjectMetadata(name=f"{source}-{consumer}-reader", namespace=namespace),
                role=role,
            ).add_subjects(
                ServiceAccount.from_service_account_name(scope, f"{source}-{consumer}-reader", READER, namespace_name=consumer)
            )
    return ClusterSecretStore(
        scope,
        "external-creds-store",
        metadata=ApiObjectMetadata(name=store_name(namespace)),
        spec=_referent_store_spec(  # the cluster CA provider, authenticating as each consumer's READER
            remote_namespace=namespace,
            consumers=sorted(set().union(*(credential.consumers for credential in credentials))),
        ),
    )

    `local_identity`, else in the SeaweedFS namespace). The operator writes that identity's key pair into
    Secret `<name>-s3-credentials`, or `secret_name` where a live consumer already reads another name.
    A grant admits exactly the kinds this puts outside the SeaweedFS namespace. Everything Retains."""

    def __init__(
        self,
        scope: Construct,
        id: str,
        *,
        name: str,
        tenant: str,
        local_identity: bool,
        adopt_existing: bool,
        description: str,
        secret_name: str | None = None,  # None: `<name>-s3-credentials`
    ) -> None:
        super().__init__(scope, id)
        described = {"description": description}
        identity_namespace = tenant if local_identity else seaweedfs_namespace.NAME
        secret = SecretRef(namespace=tenant, name=secret_name or f"{name}-s3-credentials")
        self.bucket = Bucket(
            self,
            "bucket",
            metadata=ApiObjectMetadata(name=name, namespace=tenant, annotations=described),
            cluster_ref=BucketSpecClusterRef(name=cluster.NAME, namespace=seaweedfs_namespace.NAME),
            access=[BucketAccess.read_write(name)],
            adopt_existing=adopt_existing,
            reclaim_policy=BucketSpecReclaimPolicy.RETAIN,
        )
        self.identity = S3Identity(
            self,
            "identity",
            metadata=ApiObjectMetadata(name=name, namespace=identity_namespace, annotations=described),
            seaweed_ref=S3IdentitySpecSeaweedRef(name=cluster.NAME, namespace=_seaweed_ref_namespace(identity_namespace)),
            reclaim_policy=S3IdentitySpecReclaimPolicy.RETAIN,
        )
        self.credentials = S3Credentials(
            self,
            "credentials",
            metadata=ApiObjectMetadata(name=name, namespace=tenant),
            seaweed_ref=S3CredentialsSpecSeaweedRef(name=cluster.NAME, namespace=_seaweed_ref_namespace(tenant)),
            identity_ref=S3CredentialsSpecIdentityRef(name=name),
            secret_ref=S3CredentialsSpecSecretRef(
                name=secret.name,
                access_key_field=AWS_ENV_KEY_FIELDS.access_key,
                secret_key_field=AWS_ENV_KEY_FIELDS.secret_key,
            ),
            reclaim_policy=S3CredentialsSpecReclaimPolicy.RETAIN,
        )
        self.access_key = secret.key(AWS_ENV_KEY_FIELDS.access_key)
        self.secret_key = secret.key(AWS_ENV_KEY_FIELDS.secret_key)
        if tenant != seaweedfs_namespace.NAME:
            kinds = ["Bucket", "S3Credentials", *(["S3Identity"] if local_identity else [])]

                self,
                "grant",
                metadata=ApiObjectMetadata(name=f"{tenant}-{name}", namespace=seaweedfs_namespace.NAME),
                spec=ResourceReferenceGrantSpec(
                    from_=[ResourceReferenceGrantSpecFrom(group=_GROUP, kind=kind, namespace=tenant) for kind in kinds],
                    to=[ResourceReferenceGrantSpecTo(group=_GROUP, kind="Seaweed", name=cluster.NAME)],
                ),
            )

13Rejected alternatives

Alternative Why not
Constructs mixins for pod policy (construct.with_(Hardened(), Pinned(...)), proposal A)

It is the same eager subtree walk as harden(), with identical effect when checked. But it adds jsii IMixin ceremony (@jsii.implements fails on a frozen dataclass), silently skips unsupported constructs where the function raises, and a chart-level call would pin every workload in the chart.

A pure PodPolicy.apply over k8s.PodSpec before construction (proposal B)

cdk8s-plus always renders a container securityContext, so owning those fields requires converting all 20 fluent workloads to raw, which drops cdk8s-plus defaults and re-selects Deployments that use the default selector. It also needs getattr-based evolve over jsii structs (STYLE's dynamic-probing rule) and a to_json bridge for CRD pods, and as specified it cannot express Pods that need their ServiceAccount token.

Python-side builders that collect values and construct in build()

Works without Lazy or patches, but anything added after build() is silently lost, and accumulating across charts needs a shared builder object, which is a registry by another name. Passing the whole list to the constructor needs neither.

An intermediate model: need records with one renderer each, and an HttpService archetype (proposal C)

It is the parallel deployment specification PLAN.md F forbids, and its own examples already broke the 'facts only' guard (Database carried size and storage class). Its per-namespace SeaweedFS Tenant cannot be built where one namespace's buckets belong to several Kustomizations (namespace monitoring holds separate mimir and tempo grants). The archetype silently added default-deny CiliumNetworkPolicies.

Synth-time rendering: Lazy, to_json overrides, App resolvers

Lazy raises in typed slots (#8067). A to_json override rewrites wire JSON where no reader looks, and resolvers are global. The one recorded use: a JSON patch of a core PodSpec into a CRD slot is filtered by the CRD's generated toJson, and a to_json override is not, so that route stays available if CRD pods are ever authored in the core dialect.

Chart-singleton accumulators and JSON-patch append methods (#8035's _ClusterGrant and Bucket.grant)

They are the Python-only emulation of Lazy accumulation, with raw dict patch values and a lookup by construct id. Per-bucket grants make them unnecessary: namespace monitoring already has two coexisting grants (mimir and tempo), and loki has its own.

Per-pair single-secret stores built from the consumer's chart (single_secret_store, proposal A's SecretCopy)

They put source-side RBAC in the consumer's Kustomization and keep a second authorization mechanism beside the roster the owner named as the standard (#7455).

TypedDict kwargs spreads (#8109's hardened_pod_defaults, #8104's LONG_LIVED_CA)

Policy belongs on a function's defaults or in harden(). A spread hides which fields are set, the owner has not ratified it, and it cannot reach raw or CRD pod specs.

Composite functions returning None, with knobs kept for byte-identical output (#8114)

Callers must re-spell the names the function discarded, contrary to SKILL.md:24. Knobs for one caller are the #7461 thin-wrapper problem in another form.

A Flux component or node class that owns its chart and registers its artifact (#7444)

cluster/cdk8s/AGENTS.md:98-101 and PLAN.md F forbid it. RenderedDirectory delivers the same derivation as a plain value, without a class, registry or callback.

Deriving Flux dependsOn from what a chart renders

The kind-to-provider map already exists (cluster/validation/crd_layering.py OPERATOR_CRDS), so derivation would be easy, and it is still rejected: choosing predecessors from rendered kinds makes the graph implicit, turns the map into the 'provides' registry the boundaries forbid, and would bury the rare ordering exceptions among derived edges.

The map is sanctioned for checking instead: predecessors stay hand-passed, and a synth-time validation uses it to fail an edge nothing admission-related justifies and a rendered kind that does not reach its provider.

A readiness-ordered Flux graph: a unit per concern, an edge for everything a unit needs at runtime, wait: true by default

It is what the graph grew into, and the owner is moving away from it because the tiny units cost reconcile time and I/O (#7094). On devel 1faf6d5f22, 271 of 426 edges wait on runtime state that converges by retry, 101 unsuspended wait: true nodes gate nothing admission needs, and one postBuild ConfigMap sits upstream of 118 nodes.

A third ordering-exception reason for the edges a Helm chart's custom resources need

Those edges are admission edges the rendered objects cannot show. Stating the chart's kinds at the writer (chart_kinds) lets the check verify them like any other edge, and it keeps ORDERING_EXCEPTIONS to #7094 rule 2's two reasons.

Kyverno mutation as the source of defaults for generated Pods

The snapshot and the fleet rules cannot see it, so generated output would misstate what runs. Kyverno stays for Pods the generator does not author.

A proactive tier migration, all raw to cdk8s-plus or all cdk8s-plus to raw

pod_policy and the references work on both tiers, so a migration buys churn and selector hazards with nothing gained. Workloads move when they are touched, and new ones follow AGENTS.md's tier-1 preference.

Generating variables.tf from the pydantic vars model

It moves ownership of the module interface into the generator, and a relation test between two live artifacts already catches the drift.

14How this was made

The proposal was made in five steps, each by independent agents that could read the repo and run cdk8s in a scratch environment:

  • Inventory: ten parallel sweeps covered every shared helper, per-concern wiring, open PRs and your review comments since the cdk8s layer began, planned and foreseeable needs, and what cdk8s and cdk8s-plus actually allow from Python.
  • Design: four designers each proposed a complete convention set from a different angle: construct-centric, values-first, an intermediate model, and consolidating what exists.
  • Judging: three judges scored every proposal on every need through one lens each: feasibility in Python, fit with your stated preferences, and maintainability and migration cost. A synthesizer started from the best-scoring proposal and grafted in what the judges singled out.
  • Verification: one agent per example tried to break it, and a critic checked the whole design against your original request.
  • Revision: the Flux graph on devel was measured against the admission-only direction (#7094), and the conventions, matrix, decisions, migration and examples were revised to match.

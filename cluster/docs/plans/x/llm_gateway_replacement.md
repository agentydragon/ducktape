# LLM gateway replacement requirements

This records the current LiteLLM contract for a later replacement review. It describes
requirements and gaps from the checked-in configuration; it does not compare products.
`Must` means a current dependency or an explicitly confirmed target requirement. `Should`
marks a desired future path that is not required in v0. `Nice` marks an optional or inactive
capability to retain when practical. The current custom proxy image pins
`litellm[proxy]==1.103.0`; older investigation notes can describe behavior observed under
1.100.1. [requirements.in:1-6](../../../../tana/litellm_proxy/requirements.in#L1)

The owner uses Claude and Codex subscriptions. Most Claude Code use is through the official
Claude Code Web and CLI paths outside LiteLLM; a future Claude subscription route through a
trace-collecting proxy is desired. Other provider routes may be useful when cost-effective.
The inventory also records routes used by other callers.

## Trace fields and paths

The current proxy config selects `langfuse_otel` and `prometheus`, supplies Langfuse
project keys and the OTEL host, and enables OTEL v2 message capture at `span_only`. With
those keys present, the legacy callback also writes Langfuse observations. The June tracing
note observed a `GENERATION` `litellm_request`, a `SPAN` `raw_gen_ai_request`, and related
OTEL event rows for one Responses request. Langfuse v4 now uses `events_only` / `direct`
ingestion. Langfuse currently stores traces in the cluster's central replicated ClickHouse;
the owner accepts another backend if its in-cluster storage survives a node outage. The
replacement should retain structured request traces in one trace store and avoid copying
prompt/output content to pod logs or Loki. The current config comments that a console
exporter would write captured prompts to pod logs, but no `OTEL_EXPORTER` is set; the exact
source of the observed duplicate stdout content remains unresolved. The central ClickHouse
has one shard, two data replicas on separate nodes, and a three-member Keeper quorum. Its
replicas tolerate a node outage while the other replica and Keeper quorum remain available;
permanent loss of a node's local disk still requires restore or rebuild. [proxy.py:160-182](../../../cdk8s/litellm/proxy.py#L160),
[tracing note:15-24](../../../debug/2026-06-05-litellm-responses-langfuse-otel.md#L15),

## Current pain points

- **Trace payloads are duplicated in the current Langfuse store and Loki.** The owner wants structured request traces retained in one trace store and does not want prompt/output copies in pod logs or Loki; they are open to replacing Langfuse. Their current understanding is that LiteLLM has no switch to suppress the console copy while keeping trace export. The checked-in proxy config says a console exporter would write prompts to pod logs, sets Langfuse as the exporter, and omits `OTEL_EXPORTER`; a config test checks that omission. The exact runtime source of stdout content remains unverified. [Responses Langfuse root-observation issue](https://github.com/agentydragon/ducktape/issues/5761), [proxy.py:178-182](../../../cdk8s/litellm/proxy.py#L178), [test_config.py:52-59](../../../cdk8s/litellm/test_config.py#L52)
- **The historical z.ai failure is a separate path.** The June note's `glm-4.6` `/v1/responses` failure was a LiteLLM Responses-to-chat bridge path configured with `use_chat_completions_api=true`; it is not evidence that current ChatGPT Responses traces fail. z.ai is absent from the current route roster. [Tracing note:26-40,73-104](../../../debug/2026-06-05-litellm-responses-langfuse-otel.md#L26)
- **Model naming still has compatibility edges.** [model roster naming issue](https://github.com/agentydragon/ducktape/issues/4823) captures earlier name confusion and coordinated caller/key migrations. Current routes use provider/wire/model names, but retained aliases and client pins still make route renames cross-cutting. [catalog.py:6-66,751,755-779](../../../../model_catalog/catalog.py#L6)
- **Provider prefix preprocessing can block health handlers.** A public `chatgpt/` alias invoked LiteLLM's synchronous interactive auth before router selection and caused an actual liveness restart. The deployed `chatgpt-sub/` prefix is the mitigation; stale callers can still trigger the old path. [liveness lesson:5-47](../../lessons_learned/2026_10_22_litellm_chatgpt_alias_liveness.md#L5)
- **Crossplane provider changes are part of the gateway's operational surface.** The key ownership move required a patched provider for root-scoped Keys and write-only key state, plus ordered Tofu teardown, ESO exports, and a separate BuildBuddy sync. The recovery note records that the patched provider was installed and all 12 Keys and three Teams were Ready at its 16:07 UTC check; it also documents the Team deletion cascade and write-only-key reconciliation hazards. [crossplane debug:1-9,30-40](../../../debug/2026_10_22_litellm_crossplane.md#L1), [provider package pin](../../../cdk8s/crossplane.py#L28), [provider build workflow](../../../../.github/workflows/crossplane-provider-litellm.yml)
- **Cost does not equal subscription billing.** LiteLLM and Langfuse estimates are useful for token/model attribution, but flat-rate ChatGPT/Claude subscription routes do not incur the displayed per-token bill. [props config.toml:47-61](../../../../props/deploy/config.toml#L47), [litellm-claude.nix:18-20](../../../../nix/home/claude_code/litellm-claude.nix#L18)
- **Langfuse v4 changed its ingestion layout.** The migration is complete on `events_only` / `direct`; a candidate that keeps Langfuse must preserve trace and event ingestion under the current deployment, not assume the prior observation tables are the only query surface. The owner is open to a different backend. [migration note:1-3](../../../debug/langfuse_v4_migration_20261022.md#L1)

## Open questions for the owner

No owner decision blocks replacement evaluation. Per-key limits may be omitted; if offered, any sane token-based time window that blocks requests at the limit is acceptable. Traces must remain in durable cluster storage through a node outage, and Langfuse is optional.

- If optional per-key limits are implemented, select a sensible token threshold and window; avoid USD caps that do not represent subscription or local-backend costs.
- At evaluation time, decide which optional providers are cost-effective to keep (including Groq, Mistral, z.ai/GLM, Antigravity, and Tana); Tana may remain a separate LiteLLM instance.

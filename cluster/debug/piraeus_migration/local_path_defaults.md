# Local-path claim template audit

Audit for step 6 of [the Piraeus production plan](../../docs/plans/piraeus_production.md#remaining-local-path-pvc-migration-sequence). This records the checked-in source and rendered values; it is not a fresh cluster inventory. Migration state below comes from the dated reports in this directory. Refresh live state and follow the [node-roll runbook](../../docs/runbooks/piraeus_node_roll.md) before any storage operation.

## Search and scope

The tracked-repository search was:

```sh
git grep -n -I 'local-path'
```

The search output was used to identify source files and workload objects. I then searched workload storage selectors and claim templates with:

```sh
git grep -n -I -E 'storageClass(Name)?:|cacheStorageClassName:|scratchSpaceStorageClass:|volume_storage_class:|volumeClaimTemplate|walStorage:'
```

This candidate search was cross-checked against current `devel` with GitHub Code Search (`repo:agentydragon/ducktape local-path`) and source/manifests fetched from `refs/heads/devel`. The audit below covers declarations in `cluster/cdk8s`, rendered `cluster/generated` and `cluster/k8s`, active hand-written `props/deploy` and `loom/wayback/deploy`, and parked workload manifests. The rest of the `local-path` hits are provider/class definitions, host paths, tests and fixtures, migration evidence, documentation, archived manifests, or the checked-in historical `props/specimens` snapshot. They are not active workload claim templates. `walStorage` has no declaration in the current cdk8s source or rendered cluster manifests.

I checked for default PVC StorageClass annotations and fields with:

```sh
git grep -n -I -E 'is-default-class|defaultClass' -- cluster/cdk8s cluster/generated cluster/k8s
```

That search found only the OpenEBS snapshot class default annotation; no PVC StorageClass is marked default.

`local-path-*` provisions node-local directories. `piraeus-ssd-local` and `piraeus-hdd-local` are Piraeus strict-local single-copy classes. A class in source describes future claims; it does not change the class, PV, or data of an existing claim.

## StorageClass definitions and default recommendation

`cluster/cdk8s/local_path_provisioner.py` renders the `local-path-*` StorageClasses in `cluster/generated/local-path-provisioner/local-path-provisioner.k8s.yaml`. These are provider definitions, not workload claim templates. None has `storageclass.kubernetes.io/is-default-class: "true"`. The only default-class annotation found in the generated storage configuration is `snapshot.storage.kubernetes.io/is-default-class: "true"` on the OpenEBS snapshot class; it does not select PVC storage. The Piraeus SSD/HDD StorageClasses are rendered by `cluster/cdk8s/piraeus.py` and also have no default-class annotation.

**Recommendation: keep the cluster without a default StorageClass.** A local-path default could node-pin any PVC that omits its class and recreate the old layout. Making either current Piraeus class the default would silently place unspecified claims on single-copy strict-local storage; those claims could be unschedulable when the selected node has no pool and have no second copy for node loss. Keep each workload's storage class explicit.

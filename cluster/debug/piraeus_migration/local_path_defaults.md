# Local-path allocation audit

Audit for step 6 of [`piraeus_production.md`](../../docs/plans/piraeus_production.md#6-remove-local-path-defaults-that-could-recreate-the-old-layout). This records source declarations, generated manifests, retained/parked declarations, and read-only live observations. A bound legacy PVC is not evidence that the current Pod uses it; the table calls out old retained claims separately.

## Search and scope

Searches used:

```sh
git grep -n -I -i -E 'local[-_ ]path|localpath' -- ':!*.lock'
git grep -n -I -E 'storageClass(Name)?:|cacheStorageClassName:|scratchSpaceStorageClass:|volume_storage_class:|volumeClaimTemplate|walStorage:' -- cluster/cdk8s cluster/generated cluster/k8s cluster/parked cluster/archive props/deploy loom/wayback/deploy
rg -n -i 'storage.?class|volume.?claim.?template|cacheStorageClass|cache_storage_class|persistent.?volume' cluster/cdk8s --glob '*.py' --glob '!**/test*' --glob '!**/testdata/**'
git grep -n -I -i -E 'storageclass\.kubernetes\.io/is-default-class|storageclass\.beta\.kubernetes\.io/is-default-class|snapshot\.storage\.kubernetes\.io/is-default-class|isDefaultClass' -- cluster/cdk8s cluster/generated cluster/k8s cluster/parked
```

The first command searches all tracked repository paths except lockfiles. The second identifies workload storage fields in the active cdk8s source, generated and hand-written cluster manifests, archived cluster manifests, and the active `props/deploy` and `loom/wayback/deploy` packages. It also finds parked cluster declarations. The repository-wide search returns historical `props/specimens` snapshots, the archived kagent manifest, a k3s test fixture, documentation, migration evidence, provider wiring, host paths, test fixtures, namespace names and metrics labels; those are classified as non-active references here rather than treated as production claim defaults. The generated Tofu CRD's schema text mentions `storageClassName` and `volumeClaimTemplate`; it is an API schema, not a workload claim template. `cluster/cdk8s/manifest_roots.py` confirms `cluster/parked/` is not reconciled, but those declarations remain listed because revival could restore them. The CNPG storage/WAL scan finds no `walStorage` declaration in cdk8s or generated cluster manifests.

The latest live PVC and Pod observations available to this audit were gathered read-only through Agentplane Actions on 2026-10-24. They show which claims are bound and which matching Pods are running, but do not replace data-copy acceptance evidence. The `StorageClass` list response did not expose annotations; the fetched `seaweedfs-ovh` object had only a description calling it the app-data default. The source search found no PVC default-class annotation; the separate OpenEBS snapshot-class default is not a PVC StorageClass default. Refresh cluster state before any storage operation.

## Change candidates

The source changes supported by current migration evidence are SeaweedFS master persistence, Langfuse Valkey, OCI-cache Valkey, Loki writers and Mimir ingesters. Each should be a separate draft PR. Their StatefulSet claim templates are immutable: the PR description must tell the operator to capture current Pod UIDs, PVC names and PV identities; delete only the relevant StatefulSet with `kubectl delete sts <name> --cascade=orphan`; reconcile the owning Flux Kustomization; and verify Pod UIDs, PVC names and PV identities are unchanged. These are operator steps for after review; this audit did not perform them.

Do not change ClickHouse data/Keeper, Alertmanager, Seaweed legacy volume servers, sandbox state, ActivityWatch, retained Grocy PVCs, or parked apps until the evidence gaps or remaining members listed above are resolved.

# plaid-mcp

Self-contained Plaid link management and synced Postgres read path.

## Architecture

The deployment has two public surfaces:

```text
Browser -> https://plaid-mcp.allegedly.works/link
  Gateway -> plaid-mcp web UI (:8080) -> Authentik OIDC login + signed session
    - creates Plaid Link tokens for a chosen institution's supported products
    - exchanges public_tokens
    - writes per-Item access-token Secrets in the plaid-mcp namespace
    - runs initial sync into CNPG Postgres

Claude / MCP client -> https://plaid-db.allegedly.works/mcp
  Gateway -> mcp-oauth-facade (:8765) -> EnterpriseDB Pg Airman MCP Streamable HTTP (:8000)
    - Authentik OAuth app: plaid-db-mcp
    - database role: plaid_ro
    - Pg Airman restricted mode keeps SQL execution read-only
```

There are no bespoke Plaid MCP tools. Agents read `links`, `accounts`,
`transactions`, holdings, liabilities, snapshots, `sync_runs`, and
`plaid_api_events` through SQL.

## Storage

- `plaid-mcp-db` is the CNPG cluster.
- `plaid-mcp-db-app` is the writer credential used by the web app and sync CronJob.
- `plaid-mcp-db-readonly` is generated by ESO for the read-only `plaid_ro` role,
  used by the Postgres MCP and pgweb and copied by ESO into `haku-sandbox` for Haku's
  ad-hoc queries, so all share one revocable read-only credential. The copy reads through a
  store that reaches only this Secret, and refreshes every 10 minutes.
- `plaid-pgweb-auth` is the HTTP Basic password of pgweb's `plaid` user, minted by ESO. The
  agentplane-staging egress proxy reads a copy of it; nothing else outside pgweb does.
- `plaid-client-credentials` is a SOPS-managed Secret in this namespace.
- `plaid-link-oidc-config` is minted in the `authentik` namespace by
  `tf/gitops/sso-providers`; a get-only SecretStore and ExternalSecret copy it
  here for the web Deployment. Only the OIDC reader ServiceAccount can read that
  source Secret. The sync CronJob receives none of the OIDC values.
- Plaid access tokens are stored one Secret per linked Item and are not written to Postgres.
- `plaid_api_events` is append-only and stores redacted Plaid request/response metadata.

## SQL For Sandboxes

```text
sandbox -> agentplane-staging egress proxy -> plaid-pgweb (:8081) -> plaid-mcp-db as plaid_ro
```

pgweb is a stock PostgreSQL browser whose JSON API runs a query and returns its rows
(`cluster/cdk8s/plaid_mcp/pgweb.py`). A sandbox bound to the `plaid-pgweb` egress policy
sends a placeholder for the password and the proxy presents the real one, so the password
never enters the sandbox:

```bash
curl -s -u plaid:agentplane-credential-plaid-pgweb \
  --data-urlencode 'query=select count(*) from transactions' \
  http://plaid-pgweb.plaid-mcp.svc.cluster.local:8081/api/query
```

The answer is JSON (`columns`, `rows`, `stats`); `GET /api/query?format=csv&query=...` answers
CSV. `/api/objects` lists the tables and views and `/api/tables/<name>` describes one. The
policy admits those API routes only, and POST only on `/api/query`: pgweb's session routes
and web UI stay unreachable.

What keeps it read-only, strongest first: `plaid_ro` can only SELECT; the session is
`--readonly`; pgweb refuses statements with write keywords. The last is a filter, not a
boundary. Callers read everything `plaid_ro` can, the same as the Postgres MCP. pgweb is
locked to its one connection, cancels a query after 60 seconds, and only the egress proxy may
reach it (the `plaid-pgweb` network policy).

## Link And Sync

Use `https://plaid-mcp.allegedly.works/link` to add or remove links. Pick the institution
in the typeahead; the UI looks up what that institution supports and offers exactly the
products this app can mirror, so Link is never opened requesting a product the bank
lacks — which would fail the whole session.

`plaid-mcp-sync` runs every 12 hours and performs the full-refresh mirror. It
uses date-window `/transactions/get` and `/investments/transactions/get`, not
stateful `/transactions/sync` cursors yet. It does not call real-time balance
endpoints; cached balances from product responses are snapshotted into Postgres.

## Verification

```bash
kubectl -n plaid-mcp get cluster plaid-mcp-db
kubectl -n plaid-mcp get deploy plaid-mcp plaid-db-mcp plaid-pgweb
kubectl -n plaid-mcp get cronjob plaid-mcp-sync
curl -i https://plaid-mcp.allegedly.works/link
curl -i https://plaid-db.allegedly.works/mcp
```

Expected external behavior:

- `plaid-mcp.allegedly.works` redirects unauthenticated browser requests to the app's Authentik OIDC login.
- The UI and its `/api/*` endpoints require a valid signed app session; only `/healthz` and OIDC endpoints are public.
- `plaid-db.allegedly.works/mcp` returns the MCP facade OAuth challenge until a client authenticates.

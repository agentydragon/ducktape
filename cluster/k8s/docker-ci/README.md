# Docker CI (DinD)

Persistent Docker-in-Docker daemon for CI container tests. Caches image layers
across test runs, avoiding the ~46s cold-pull penalty on disposable RBE executors.

## Architecture

```text
Bazel host (bbr runner / Claude container / dev laptop)
  │  sops -d → DUCKTAPE_DOCKER_CLIENT_KEY env var (base64-encoded PEM)
  │
  ▼
bbr test //...
  │  --remote_run_header passes client key (not cached)
  │
  ▼
BB runner VM
  │  env var forwarded to Bazel via env_inherit
  │
  ▼
RBE executor (Firecracker)
  │  pytest fixture (docker_mtls) decodes key, assembles cert dir from:
  │    - env var (client key, base64)
  │    - runfiles (ca.pem, client-cert.pem)
  │  sets DOCKER_HOST, DOCKER_TLS_VERIFY, DOCKER_CERT_PATH atomically
  │
  ▼
DinD pod (k8s, OVH) — mTLS on tcp://docker-ci.allegedly.works:2376
```

## mTLS Certificate Setup

All certs are ECDSA P-256, 10-year validity, signed by a dedicated CA.

| File                   | Location             | Encrypted                 | Purpose                                      |
| ---------------------- | -------------------- | ------------------------- | -------------------------------------------- |
| `ca.pem`               | `certs/`             | No                        | CA certificate (public)                      |
| `server-cert.pem`      | `certs/`             | No                        | Server cert, SAN=`docker-ci.allegedly.works` |
| `client-cert.pem`      | `certs/`             | No                        | Client cert, EKU=clientAuth                  |
| `server-tls.sops.yaml` | this dir             | SOPS (cluster-secrets)    | Server private key (k8s Secret)              |
| `ca-key.sops.pem`      | `secrets/docker-ci/` | SOPS (admin)              | CA private key (for rotation)                |
| `client-key.sops.pem`  | `secrets/docker-ci/` | SOPS (admin + claude-web) | Client private key (for CI)                  |

### Secret flow

**Server side** (k8s): Flux decrypts `server-tls.sops.yaml` → k8s Secret. Public certs
served via ConfigMap (generated by kustomize from `certs/`). DinD pod mounts both.

**Client side** (CI): The Bazel host decrypts `secrets/docker-ci/client-key.sops.pem`,
base64-encodes it, and exports `DUCKTAPE_DOCKER_CLIENT_KEY`. `bbr` passes it to
the runner via `--remote_run_header` (not cached, not visible in BB UI). `env_inherit`
carries it from the runner to the RBE executor. The `docker_mtls` pytest fixture
base64-decodes the key, writes it to a temp cert dir alongside the public certs from
runfiles, and atomically sets `DOCKER_HOST`, `DOCKER_TLS_VERIFY`, and `DOCKER_CERT_PATH`.

### Setting up the environment

```bash
# Handled by ci_env.sh (sourced from .envrc):
# export DUCKTAPE_DOCKER_CLIENT_KEY=<base64-encoded PEM>
```

`bbr` automatically forwards this when `DUCKTAPE_DOCKER_CLIENT_KEY` is set.
The `docker_mtls` pytest fixture assembles the full Docker mTLS env from this single var.

### Rotating certificates

```bash
# Generate new certs (same process as initial generation)
openssl ecparam -genkey -name prime256v1 -noout -out ca-key.pem
openssl req -new -x509 -days 3650 -key ca-key.pem -sha256 -out ca.pem -subj '/CN=Docker CI CA'

# Server cert
openssl ecparam -genkey -name prime256v1 -noout -out server-key.pem
openssl req -new -key server-key.pem -sha256 -out server.csr -subj '/CN=docker-ci.allegedly.works'
# SAN covers both the external name (RBE runners via the gateway TLSRoute) and the
# in-cluster service name (the loom/gym eval Job connects direct, bypassing the
# agent mitmproxy via NO_PROXY — see loom/gym/k8s/eval-job.yaml).
printf 'subjectAltName=DNS:docker-ci.allegedly.works,DNS:docker-ci.docker-ci.svc.cluster.local\nextendedKeyUsage=serverAuth\n' > ext.cnf
openssl x509 -req -days 3650 -sha256 -in server.csr -CA ca.pem -CAkey ca-key.pem \
  -CAcreateserial -out server-cert.pem -extfile ext.cnf

# Client cert
openssl ecparam -genkey -name prime256v1 -noout -out client-key.pem
openssl req -new -key client-key.pem -sha256 -out client.csr -subj '/CN=docker-ci-client'
printf 'extendedKeyUsage=clientAuth\n' > ext-client.cnf
openssl x509 -req -days 3650 -sha256 -in client.csr -CA ca.pem -CAkey ca-key.pem \
  -CAcreateserial -out client-cert.pem -extfile ext-client.cnf

# Update files
cp ca.pem server-cert.pem client-cert.pem cluster/k8s/docker-ci/certs/
cp server-key.pem cluster/k8s/docker-ci/server-tls.sops.yaml && sops -e -i cluster/k8s/docker-ci/server-tls.sops.yaml
cp ca-key.pem secrets/docker-ci/ca-key.sops.pem && sops -e -i secrets/docker-ci/ca-key.sops.pem
cp client-key.pem secrets/docker-ci/client-key.sops.pem && sops -e -i secrets/docker-ci/client-key.sops.pem
```

## Kubernetes Resources

- **Namespace**: `docker-ci` (privileged PSA — DinD requires it)
- **Deployment**: `docker:27-dind` with `--tlsverify`, scheduled on OVH workers
  (`topology.kubernetes.io/region: hil`)
- **Storage**: `emptyDir` (30Gi) for `/var/lib/docker` — a disposable overlay2
  cache, hence no PVC (rationale in `deployment.yaml`).
- **Service**: ClusterIP on port 2376
- **ConfigMap**: `docker-ci-public-certs` (ca.pem, server-cert.pem)
- **Secret**: `docker-ci-server-tls` (server-key.pem, SOPS-encrypted)

## Maintenance CronJobs

- **Container prune**: hourly, removes stopped containers older than 1h
- **Image prune**: weekly (Sunday 3am), removes unused images older than 7 days

Both use `kubectl exec` into the DinD pod via a dedicated ServiceAccount.

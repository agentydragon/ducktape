# Agentplane runner lifecycle ownership map

**Scope:** source-based map of Session admission, Runner execution, and Sandbox shutdown ownership. No runtime changes, cluster operations, or lifecycle tests were run for this investigation. Anchors refer to the source at the report commit.

## Entry paths and lifecycle transitions

**Open.** The browser creates a stable UUID before the request. Dispatcher stores an Opening under that ID; its delivery worker sends it to the current Runner owner. `Runner.OpenSession` validates the ID, serializes creates, and persists a Session record before the Session is made available. Repeating the same ID/spec returns the existing Session; a conflicting spec is rejected. The persistent ID is the join key across browser recovery, Dispatcher, Runner storage, and History. See [client ID handling](../app/frontend/sandboxes/sandbox_page.tsx#L183-L214), [Dispatcher opening](../runner_gateway/dispatcher/api.go#L264-L311), and [Runner creation](../runner/runner.go#L415-L509).

**Command.** The app forwards a user command with its command ID to Dispatcher. Dispatcher commits a `QUEUED_IN_DISPATCHER` row before reporting queue state. Its delivery worker selects the Session head, claims it under the live owner fence, and calls the Runner through Gateway's control tunnel. The Runner journal atomically records `CommandAdmitted`; only then can the Dispatcher settle the row as Runner-admitted. The Runner later writes terminal outcomes as it observes native behavior. `DispatchPlanned` is persisted before native I/O, but its presence cannot prove that retrying the native write is safe, so uncertain writes remain pending rather than being resent ([dispatch boundary](../runner/session.go#L668-L765)).

**Quiesce and stop.** A user/declarative suspend, idle timeout, or deletion enters the Sandbox Controller path. For idle suspension, the controller passes the exact `idle_since` fact into Quiesce; a Runner that became busy or has a different idle instant aborts. A wake racing the suspension status write is fenced by Kubernetes resource version and `WakeGeneration` ([idle path](../sandbox_controller/idle.go#L76-L143)). For stop/delete, the controller persists a quiesce attempt and holds the current incarnation until its lease facts report quiesced ([controller quiesce](../sandbox_controller/controller.go#L304-L386)).

The Runner sets durable lameduck and a lifecycle goal while holding its RPC admission barrier. Its controllers then drain in stages: finish command admissions; halt Sessions and join setup/dispatch/control workers; interrupt active turns and wait for them; stop dedicated harnesses and the shared Codex process; fence the executor; settle bootstrap and inspections; then seal each journal with the current incarnation UID. Quiesce reaches `QUIESCED` only after History has acknowledged each exact final seal cursor. The lifecycle is staged through observed controller state rather than one shutdown worker ([controller implementation](../runner/lifecycle.go#L821-L990), [lifecycle contract](../runner/docs/lifecycle.md#L63-L111)). The Sandbox Controller can then stop the Pod/VM. A replacement Runner adopts the new incarnation only after the old one has reached flushing and native cleanup/seals are complete; it does not wait for old-ingress acknowledgement before adopting ([adoption](../runner/runner.go#L257-L334)).

## Three completion boundaries

These states are intentionally distinct:

1. **Dispatcher admission:** the command row is committed as queued. This proves durable queue acceptance, not Runner receipt.
2. **Runner admission:** a `CommandAdmitted` event is committed in the Runner journal and returned by the RPC. Dispatcher can now record `RUNNER_ADMITTED`; native execution may not have started.
3. **Effect and event transport:** a harness confirmation, command terminal event, or `TurnCompleted` records observed execution outcome. Separately, the Runner's ingress cursor ack means History accepted journal entries. A transport ack does not prove a command effect completed. Quiesce has the stronger special condition that the acknowledged cursor equals the sealed journal cursor and the ack is marked sealed.

The app's archive projection may lag both Dispatcher admission and Runner journal admission, so a delayed history row is not evidence that either durable boundary failed.

## Concurrency guards to preserve

- **Stable identity and retries:** Open uses a client-minted Session UUID; ambiguous browser outcomes are checked rather than replayed. Dispatcher command IDs are idempotent only for the same Session/Sandbox/payload; conflicting reuse fails ([Dispatcher transaction](../runner_gateway/dispatcher/store.go#L175-L223)).
- **Single delivery owner and live tunnel:** per-Sandbox Lease UID/holder/transition generation is verified against PostgreSQL before external delivery; Gateway ties the connection to the authenticated Pod UID and epoch ([ownership fence](../runner_gateway/dispatcher/ownership.go#L139-L179), [Connect](../runner_gateway/gateway/control.go#L89-L110)).
- **Single state-directory writer:** the Runner's exclusive lock spans native children, so a replacement process cannot write the same journals while an old child remains live ([StateOwner](../runner/store.go#L30-L65), [supervisor](../runner/supervisor.go#L75-L173)).
- **Admission versus teardown:** `Runner.mu` counts in-flight RPC admissions and the lifecycle controller waits for zero before halting. `Session.admitMu` serializes journal admission with seal; duplicate journal admissions return their original entry before new-command validation ([Session admission](../runner/session.go#L393-L436), [journal admission](../runner/journal.go#L711-L779), [seal](../runner/session.go#L1163-L1178)).
- **Exact active-turn interrupts:** journal admission atomically compares the expected turn ID before adding a new interrupt. Dispatch checks the live turn again and installs the interrupt command under the Session mutex before calling the harness ([journal check](../runner/journal.go#L750-L779), [dispatch check](../runner/session.go#L716-L765)). Preserve both checks and their ordering; admission is not proof that the native interrupt took effect.
- **Idle-to-suspend race:** Runner validates the exact idle timestamp, and the Controller's status update uses the observed WakeGeneration/resource version so an intervening wake is reconciled rather than lost ([idle suspend](../sandbox_controller/idle.go#L76-L143)).

## One narrow simplification candidate

`runnerInputSpec.Admissions` is declared and assigned from `Runner.admissions`, but repository search finds no reader beyond that assignment. The authoritative count is read directly by the Runner lifecycle controller before it advances from draining to halting. A narrowly scoped cleanup could remove only this mirrored field and `touchRunner` sampling/assignment while retaining `Revision++` and the lifecycle publication that wakes reconciliation ([field and writer](../runner/lifecycle.go#L110-L117), [touchRunner](../runner/lifecycle.go#L340-L354), [barrier read](../runner/lifecycle.go#L844-L850)). This is a candidate, not an implemented change; the admission counter, goal generation, and close/quiesce barrier remain necessary.

If pursued, validate with `//agentplane/runner:runner_test` (race-enabled, includes lifecycle, persistence, Session, and transport tests), plus `//agentplane/runner:test_turns` and `//agentplane/runner:test_restart` for turn interruption, process fencing, and uncertain native writes. Changes to externally visible quiesce need `//agentplane/sandbox_controller:sandbox_controller_test`; Dispatcher/Gateway boundary changes also need `//agentplane/runner_gateway/dispatcher:store_integration_test` and `//agentplane/runner_gateway/gateway:gateway_test`; app-facing Open/archive changes need `//agentplane/app:test_bridge`. These are regression targets, not claims of tests run for this report.

## Findings

### PR-T01 — Keep failure settlement facts typed until the JSON/storage boundary

**Priority:** P2 · **Confidence:** high

**Evidence and causal path:**

- agentplane/x/central_sampler/executor_operations.go:727-778 defines executionFailureEvidence as map[string]any. executorEnvironmentFailureError already owns typed values (state, afterSequence, and output), but serializes them into an untyped map in executionFailureEvidence().
- agentplane/x/central_sampler/executor.go:233-243 routes that map into settlement and then into the model-visible error.
- agentplane/x/central_sampler/executor.go:295-365 drives process state from map keys and silent assertions. A missing or mistyped process_id, method, or remote_outcome becomes an empty value and can silently skip settlement. evidenceAfterSequence accepts float64; evidenceOutput silently returns nil for a wrong type, invalid base64, or failed buffer restoration.
- agentplane/x/central_sampler/executor.go:439-460 repeats the same map decoding and supplies a generic fallback message when message is absent.
- The producers have the original exact cursor and *headTailBuffer available. The current path encodes output with retainProcessObservation (executor_operations.go:833-844) and then decodes that base64 in evidenceOutput solely to settle the process. Store.AbandonProcess replaces stored output when given a buffer (store.go:2898-2922), so a decode failure would retain stale stored output rather than newer observations (for example, setup output accumulated before a later read refusal).

The present producer supplies the expected keys and types, so this audit did not establish a current malformed-map incident. The risk is that this new control path converts an internal contract drift into a successful-looking, incomplete tool failure. The float conversion also permits sequence precision loss if generic JSON-decoded facts are later passed through this helper; the current in-memory producer uses uint64.

**Minimal coherent remedy:** return a concrete executionFailureFacts value from the error boundary, with typed method/outcome/state fields, *uint64 cursor, and *headTailBuffer output. Settle the process directly from that value and make malformed or impossible combinations return an error. Convert to the durable JSON evidence map and the host's JSON-string error only after settlement. Keep the existing JSON field names and base64/full-output contract at those boundaries.

**Boundary and storage risk:** no proto or stored-data schema change is needed. Preserve remote_outcome: "unknown" for an already-started process whose read was refused, alongside request_outcome: "not_dispatched"; do not infer process state from request admission. Preserve the exact uint64 cursor and full retained bytes.

**Suggested checks (not run):** bbr test //agentplane/x/central_sampler:central_sampler_test. Add or extend a behavior test where setup/read has accumulated output and a later typed pre-dispatch read refusal occurs; assert the cursor, full bytes, and process status in both sampler_process and the intent evidence.

### PR-T02 — Give process outcome and request-admission outcome distinct internal types

**Priority:** P2 · **Confidence:** high

**Evidence:** executorEnvironmentFailureError.remoteOutcome is a plain string (agentplane/x/central_sampler/executor_operations.go:731-737), assigned "not_dispatched" or "unknown" at executor_operations.go:502-506, 779-787, and inspected as a literal in its Error() method at executor_operations.go:740-746. Settlement repeats literal comparisons for method and outcome in agentplane/x/central_sampler/executor.go:304-318. The package already has NestedOutcome, NestedUnknown, and NestedNotDispatched in agentplane/x/central_sampler/types.go:213-222; the changed transport evidence path uses those constants, while this new environment path does not.

These values are not interchangeable: for a refused process/read, the read request outcome is not_dispatched, but the process outcome remains unknown. A typo or reuse of one untyped string can send settlement down the wrong branch. The PR's spec and tests correctly preserve the two values; the implementation should encode that distinction as well.

**Minimal coherent remedy:** use a named internal process-effect outcome with explicit unknown and not_dispatched values (or the existing NestedOutcome only where its stored-intent meaning is exact), and use the generated ExecutionEnvironmentFailure.Outcome or a dedicated request-outcome type for admission. Use named constants for the internal method values that select process settlement (process/start, process/read). Convert to the lowercase external strings when serializing evidence. Keep the two fields separate through settlement; never turn a refused read into a known-not-dispatched process outcome.

**Boundary and storage risk:** preserve the current JSON vocabulary and proto enum values. A refused start may settle its not-started handle; a refused read must leave the process outcome unknown and preserve its observations. No automatic replay follows either result.

**Suggested checks (not run):** bbr test //agentplane/x/central_sampler:central_sampler_test, especially TestTypedStartEnvironmentFailureIsNotReplayed, TestTypedReadEnvironmentFailurePreservesUnknownProcessEvidence, and TestTypedWriteEnvironmentFailureDoesNotReplayInput.

## Justified non-findings

- The previous hand-maintained environment-state-name helper is absent. Production output uses the generated enum's .String(), while the wire detail itself carries the enum; this is the canonical owner.
- Unknown or unspecified proto enum values are rejected by the sampler's known-state switch and therefore remain conservative transport failures. The Gateway and sampler switches have different jobs (producer status mapping versus receiver validation); neither silently maps an unknown state to a known lifecycle state.
- JSON field names such as remote_outcome, request_outcome, and environment_state are external/durable schema keys. They need not become Go constants. Likewise, JSON maps in tests are at the serialization boundary rather than driving production control flow.
- The important read refusal behavior remains distinct in the new code: the outer process result is unknown, the request is not_dispatched, observed cursor/output are retained, and no read retry is issued. The review found no recommendation to narrow raw native-frame or opaque response payloads.
- No duplicate generated/proto enum or competing owner of the ExecutionEnvironmentFailure schema was found.

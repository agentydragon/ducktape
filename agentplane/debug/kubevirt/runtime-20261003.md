# Runner guest acceptance: 2026-10-03 UTC

Disposable namespace `agentplane-vm-prototype-runtime-20261003`, KubeVirt v1.8.2,
worker `ovh-ns103711`, storage class `local-path-ovh-hdd`. The real sandbox inventory
created VM `runner-runtime-jaap2` (UID `49c01d3e-5856-4378-866a-72a71d963dbf`),
a 20 GiB state DataVolume, and a 40 GiB workspace DataVolume. No existing
environment's disks or configuration were used.

## Failures found before acceptance

- The first provider handoff hit a resource-version conflict after clearing its
  provisioning intent. Clearing the intent and starting the VM now share one
  UID/resource-version-guarded patch. The [regression test and inventory checks](https://app.buildbuddy.io/invocation/8e689e2c-50cf-4844-88fe-7d77c6b67908)
  passed; this fix belongs to the provider integration PR.
- The first guest reached NixOS emergency mode because disk preparation failed.
  The compiled preparation unit omitted `diffutils` from its PATH despite calling
  `cmp`. Inspection also found the storage permission unit called `sh` without
  declaring Bash. Both dependencies are now explicit.
- The initial image had no serial-console kernel argument. A temporary graphical
  boot exposed the failed unit; the corrected image enables `ttyS0` diagnostics.
  Graphical display was disabled again before acceptance.

The unsuccessful initial image was the PR2 CI artifact from workflow run
`37100553096`, head `ca0c58491e5c8301434e3ed7baa37084fc214eb6`, built at merge
commit `9b75307863153608e368b6018e9216a151c82dae`. Its archive SHA256 was

The quota probe initially expected `EDQUOT`. XFS intentionally returns `ENOSPC` for
[project quota reservation failures](https://github.com/torvalds/linux/blob/v6.12/fs/xfs/xfs_trans_dquot.c#L816-L820).
The final probe required both the successful 7 GiB allocation and rejected 9 GiB
extension; an arbitrary allocation failure was insufficient.

The acceptance helper also needed two corrections: selecting launcher Pods by
`kubevirt.io/created-by=<VMI UID>` and draining failed setup streams through EOF
without racing a `Detach` write against the server's terminal close.

## Startup cost

The cold image pull took 120 seconds. Guest unit timestamps show the full blank-disk
scan and formatting took 253 seconds (06:49:54–06:54:07 UTC). Constructing the Java
trust store took another 172 seconds (06:54:11–06:57:03 UTC); the runner listened
at 06:57:07 UTC. The trust step imports 273 certificates one at a time, including
overlap between the public and supplied bundles. These are measured prototype
startup costs, not a startup-latency acceptance claim.

## Recovery results

correctly rejected while that VMI was terminating: the helper had confused a
filtered inventory view with deletion. The corrected helper waits for the raw
VMI API to return 404 before calling provider resume.

Resume created VMI UID `2072f0f9-06c7-46b2-af5a-e0ad9eb2b1fa`, launcher
`virt-launcher-runner-runtime-jaap2-rn8c4`. Both PVC UIDs remained unchanged:

`a2b1ecab-71fb-4a5e-95b7-6a5fe8048681`. Guest formatting authorization was empty.
Retained-disk preparation took 28 seconds, and the runner listened at 07:19:03 UTC.

## Scope and remaining checks

This completes the prototype guest gate: OCI boot, runner RPC, real native CLI
turns, memory/quota/capacity failures with a responsive runner, and stop/start
recovery. Production gateway credential substitution and CONNECT/TLS remain
integration work. CPU, process-count and I/O limits were read back but not pressure
tested. This run did not exercise native tool cancellation, killing the runner
mid-write, competing runner ownership, node-loss recovery, or replacing the root
image after native histories had been populated.

## Cleanup

The VM was halted and the final VMI was confirmed deleted before namespace
removal. The namespace, both retained PVCs and their Delete-policy PVs, admission
policy, cluster secret store, TokenReview role/binding, and named registry-secret
reader role/binding were removed. Both local port-forwards were stopped. The
experiment OCI tag remains available for reproduction; no deployed environment
catalog was enabled.

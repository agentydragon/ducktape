# Repeated VMI shutdown with debug kernel arguments

An uncached [BuildBuddy invocation](https://app.buildbuddy.io/invocation/557c77ec-0320-4f6b-ab51-08e19d68ecc4) ran three sequential direct-VMI shutdown cycles in one k3s/KubeVirt boot. It passed in one 385.2-second test action, without a flaky retry. The tested manual harness was the candidate later merged as [PR #14701](https://github.com/agentydragon/ducktape/pull/14701); the remote runner fetched `57f2324c1c22c308480ded41d294ed148c2e9828` and applied the worktree patch before testing. `run-config.json` confirms policy on and these opt-in guest arguments: `systemd.log_level=debug systemd.log_target=console loglevel=8`. This was a deliberate verbosity perturbation after a separate clean [two-cycle baseline](../README.md#manual-repeated-cycles).

Each `cycles/NNN/` tree has a distinct namespace, namespace UID, policy UID, PVC UID, VMI UID, and Pod UID in `cycle-identity.json`. All three `shutdown-diagnostic.json` files classify `orderly_guest_powerdown`: one guest per cycle, ordered ACPI receipt, guest shutdown-complete marker and `reboot: Power down`, plus an exact-VMI-UID-correlated virt-handler `Shutoff reason Shutdown` event. None has a correlated grace-expiry, launcher-kill, or destroyed-domain event. QMP `query-kvm` reports `enabled: false` in all three cycles, and admission records show `virtiofs-state` as a restartable init sidecar with `restartPolicy: Always`. The passing test includes UID-checked namespace, ClusterPolicy, PVC, and local PV cleanup after each cycle. The guest marker counts are ACPI handler output counts, not QMP command counts.

[`raw_artifacts.tar.gz`](raw_artifacts.tar.gz) retains all 74 BuildBuddy `test.outputs/standalone-vmi-tcg/` files plus `test.log` under the original per-cycle paths. It includes guest serial and console logs, journals, launcher and virtiofs logs, host QEMU snapshots, lifecycle traces, VMI and admission records, and the diagnostic reports. [`SHA256SUMS`](SHA256SUMS) records the archive digest; [`FILE_SHA256SUMS`](FILE_SHA256SUMS) records and verifies every unmodified file in the archive. The archive uses sorted paths and zeroed tar timestamps/ownership; it contains test-only placeholders, not production VMI content.

Before publication, the 75-file inventory and launcher Pod environment were inspected. All files, including binary journals, were scanned for private-key headers, JWTs, GitHub/AWS token formats, bearer/authorization headers, and password/API-key assignments; no credential value matched. The launcher Pods set `automountServiceAccountToken: false`, and their explicit environment contains only verbosity, runtime paths, and a Pod-name field reference. Systemd's `ConditionCredential=` log text is a condition name, not a credential value. This is a bounded content audit, not proof that arbitrary unrecognized secret formats could never appear in a raw log.

Three clean direct-VMI TCG cycles do not reproduce the historical late CI stall or establish its cause. The debug arguments increase console traffic and can change timing; this arm is not equivalent to the production-like baseline or the full Agentplane VM suite.

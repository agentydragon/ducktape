Open acceptance criteria

Open contract design

Typed Session overrides must preserve the current three-state behavior

Today. CreateSessionRequest.spec is a Struct validated against the generated SessionSpec descriptor; setup script is a Value. This intentionally distinguishes omission (inherit), explicit empty/zero (replace with empty/zero), and null (clear). A plain message or ordinary optional scalar does not express all of those states.

Accept when. A typed replacement can represent every field’s inherit/set/clear state, rejects unknown fields, preserves the setup-script tri-state, has generated HTTP/client codecs, and documents cached-client/rollback compatibility. Keep caller-minted Session ID and uncertain-outcome reconciliation intact. Do not remove the current Struct path until that migration is tested across supported replicas.

Evidence: request · behavior · open plan

Low priority · explicit presentation boundary

Action protobuf-to-UI mapping should have direct edge-case tests

The client intentionally translates generated timestamps, Value/Struct, nullable fields, enums and int64 values into a stable view model. That conversion is useful, but a broad adapter is another place protocol additions can be missed. Keep the UI view; add focused tests covering every enum and oneof mapping, optional defaults, unknown enum rejection and unsafe int64 handling. Avoid removing the safe-int or required-field checks as part of any consolidation.

Evidence: view model · int64 guard · message conversion.

Low priority · enum coverage

Policy kind mapping needs a current-vocabulary coverage check

Keep Kubernetes-authored rules, stored policy evidence and API policy kinds as separate contracts. The Go map rejects unknown values, but a new storage or protobuf enum can still be omitted from the manually maintained map and fail only when that path is exercised. Add a focused test that enumerates supported internal and protobuf kinds, verifies every intentional mapping in both directions, and rejects unspecified/unknown values. Do not collapse the three schemas into one merely because several enum strings match.

Evidence: mapping · existing golden vectors · protobuf vocabulary.

Cross-language config

Configuration parity needs a bounded producer-to-loader contract

Keep each serving component’s schema as authority, including secrets, environment overlays and runtime defaults. The App still declares Python and Go ThreadPreset shapes separately while App owns preset behavior. Add shared default, omitted and invalid vectors for their configured defaults (including cwd, reasoning effort, instructions and setup script) so default behavior is checked across both paths without collapsing owners. For one chosen serving service, run the same valid, omitted, null, invalid nested, unknown-field and required-field vectors through the Python authoring model and real Go loader; verify cdk8s output reaches that loader. A generated schema is one option, not the acceptance condition. Sidecar already has selected real-process positive coverage, as documented in the fixture audit.

Evidence: Python ThreadPreset · Go ThreadPreset · override presence semantics · typed migration plan · Notification config boundary · History config boundary.

Low priority · test-only

Browser and Python history diagnostic events still need a shared drift check

The browser producer has a TypeScript discriminated union; Playwright collection has strict Pydantic models. Keep the privacy boundary (geometry and identifiers only). Accept either generated bindings from one neutral schema or shared positive/negative round-trip vectors that fail if either side adds, omits or renames a field or event kind. The History Service’s durable protobuf is a separate protocol and should not be conflated with these test marks.

Evidence: Python variants · TypeScript variants.

Ownership rules for future changes

Boundary Authority Derived material
Service RPC and HTTP facade Owning service proto; neutral proto for values with truly shared semantics Generated Go/Python/TS and protobuf JSON decoders; thin auth/transport adapters.
Kubernetes resource Owning CRD API and served schema Generated clients plus explicit translation into service views.
App composition App-owned response contract and backend source protos Generated message joins or deliberately normalized presentation types.
Durable database rows Owning migration for storage; service-owned published row contract Queries, ORM helpers and typed wire adapters with parity tests.
Deployment config Serving component’s schema and explicit secret/default/overlay semantics Authoring bindings and runtime decoder; independent code is acceptable only with executable parity evidence.
External MCP input Upstream catalog/version Local validated adapters; do not imply Agentplane schemas own third-party payloads.

Generated types are representations, not permission to collapse lifecycle, identity, authorization or presence boundaries. Keep explicit conversion where semantics change and test that conversion.

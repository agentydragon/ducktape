# Docker exec process cleanup after timeout or cancellation

`run_session_container` closes the aiodocker exec stream when its collector times out, raises, or is cancelled. Its existing termination command inspects the exec's `Pid` and runs `kill -9 <Pid>` inside the container. That does not establish that the remote process stopped.

Docker's [ExecInspect implementation](https://github.com/moby/moby/blob/9d3170875d2491631840c2d1241f4b2a43c90dbb/daemon/inspect.go) fills `Pid` from the daemon's `Process.Pid()`. Docker's [PID namespace configuration](https://github.com/moby/moby/blob/9d3170875d2491631840c2d1241f4b2a43c90dbb/daemon/oci_linux.go) places container processes in their own PID namespace by default. The inspected PID is therefore in the daemon's namespace, while the in-container `kill` resolves a PID in the container's namespace. The two numbers may differ. The current cleanup also drains the kill exec without checking its exit code.

The Docker tests cover partial output on timeout, a following exec, collector error propagation, and caller cancellation. Caller cancellation closes the stream and propagates without running the timeout kill path. The tests do not establish that a timed-out or cancelled process is gone. Before changing the termination protocol, decide how to identify and signal the exact exec process in the container namespace, including descendants and a cancellation that arrives before the process starts. An argv wrapper or PID file would add shell and filesystem requirements and alter process ancestry, so those tradeoffs need their own review.

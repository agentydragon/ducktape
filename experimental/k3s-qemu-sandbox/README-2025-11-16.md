# K3s/Kubernetes in Claude Code Sandbox

## Top-Level Goal

**Objective:** Demonstrate a working Kubernetes environment (real or emulated) in the Claude Code sandbox environment, where Claude Code agents can:

1. Deploy Kubernetes workloads (pods, deployments, services)
2. Inspect and debug running workloads
3. Test Kubernetes YAML configurations
4. Learn and experiment with Kubernetes operations

This would enable Claude Code to help users with Kubernetes-related tasks directly in the sandbox environment, without requiring access to external clusters.

## Approaches Investigated

### 1. Native k3s on Host
**Status:** ❌ **FAILED** - gVisor kernel limitations

**What was tried:**
- Install k3s binary directly on sandbox host
- Run k3s server with minimal configuration
- Work around missing `/dev/kmsg` and cgroup support

**Result:** k3s binary installed successfully, but server failed to start due to missing kernel features in gVisor sandbox.

**See:** [FINDINGS.md](FINDINGS.md) for detailed technical analysis

### 2. QEMU + k3s in VM
**Status:** ⚠️ **BLOCKED** - QEMU installation issues

**What was tried:**
- Download and extract QEMU from Ubuntu packages
- Manually resolve dependencies
- Boot Ubuntu cloud image in QEMU

**Result:** Complex dependency chain without sudo access prevented QEMU from running.

**See:** [FINDINGS.md](FINDINGS.md#what-failed-qemu-installation)

### 3. Alternative Approaches Considered

**Not yet attempted:**
- k0s (alternative lightweight Kubernetes)
- microk8s
- kind (Kubernetes in Docker) - requires Docker
- k3d (k3s in Docker) - requires Docker
- minikube - likely same kernel issues
- Talos Linux - requires QEMU

## Current Status

**What Works:**
- ✅ k3s binary installation (v1.33.5+k3s1)
- ✅ kubectl binary available
- ✅ Unrestricted network access
- ✅ Can download images and packages

**What Doesn't Work:**
- ❌ Starting k3s server (kernel limitations)
- ❌ QEMU installation (dependency issues)
- ❌ Docker installation (requires sudo)

**What's Needed:**
- Pre-installed QEMU + dependencies, OR
- Docker daemon support, OR
- Relaxed gVisor restrictions for k8s kernel features, OR
- Pre-configured VM image with k3s, OR
- Access to external k8s cluster

Chart.js first-layout border width changes the plot by 1/13 CSS pixel

Two independent RBE probes on source 1d98f437 each started with the a327 fleet’s common dashboard-dark-390.png variant (fa43840a…, 208,262 bytes). One additional chart.update('none') at unchanged data and options produced the exact run-3 variant (13e46193…, 208,252 bytes) in both runs. Canvas size remained 292×250 CSS pixels at DPR 1; only chartArea.right moved, from 287.85625 to 287.7793269230769 (1/13 CSS pixel). Left, top, and bottom stayed fixed.

Chart.js computes getMaxOverflow() before layout, then resolves line options during dataset update. The first pass sees border width 0; a later pass sees width 2. The minimum overflow therefore changes by 1 CSS pixel. With seven offset category ticks, the axis-padding formula turns that into the measured 1/13-pixel right-edge shift. The exact PNG match connects this history-dependent geometry to the a327 dashboard variant.

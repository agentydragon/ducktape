Two-shard VM/MCP spike

The first forced-sharding attempt 5b904de0 failed before scenarios: pytest_bazel emitted shard arguments but the pytest sharding plugin was absent. One localized retry uses the repository wrapper’s shard_count=2, which loads util.testing.sharding. Production configuration is unchanged.

Both arms pass all 15 distinct cases exactly once: 12 MCP cases and three VM cases. Sharded invocation 06 takes 493.551s; unsharded control 07 takes 508.136s. The 14.585s difference comes with 1.74× remote execution-seconds and 2.31× CPU-seconds in this pair.

Workers, snapshot state and input downloads differ. The sharded actions download about 10.91GB in total versus 65.43MB for the control. A bounded CAS audit (40 directory reads) verifies identical file digests and symlinks across all four shard/control pairs; input roots differ only in empty test-output directory layout. Automatic git mirroring records different base commits, so the verified runtime inputs are stronger evidence than that metadata field. This is a successful coverage/compatibility spike and an observed cost tradeoff, not a matched 14.6-second treatment effect. Do not adopt blanket two-shard execution from this result. The prior 0–180s forecast is withdrawn as a rollout recommendation; a controlled warm/cold comparison is only worthwhile if the additional compute cost is acceptable.

Independent artifact phases: concurrent feasibility passed

The workflow currently serializes generated-policy Nix checks before the remote source-artifact build. The policy commands do not consume the built artifacts; artifact imports do, and remain after the join. A local coordinator launched the unchanged three-policy Nix command and all 18 in-gate source targets concurrently, awaited both, and retained return codes [0,0]. 5b904de0 is the artifact build.

This populated-store/cache smoke establishes coexistence, not a GitHub-host speedup or a rerun of the artifact import checks. The 28s / 31s ideal overlap is measured from paired existing CI step intervals (n=147), and ignores new resource contention/coordinator cost. It is a concrete low-risk source PR candidate; full affected-artifact selection remains deferred because it is more complex and the remaining gate headroom is small.

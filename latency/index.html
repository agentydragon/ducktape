Runners and capacity — do self-hosted runners help?

Completed core-workflow occupancy was 99.2 runner-hours in 24.9 h (mean 4.0 busy, peak 20 = the hosted concurrency limit). Only 28.9 of 1,495 minutes had ≥18 core jobs busy, and just 916 of 7,408 PR Test & Build queue-seconds (12%) fell inside those minutes. PR queue is 3 / 88 s p50/p90. A cluster-hosted GitHub runner pool would therefore buy ≤ ~1–1.5 min at p90 and nothing at p50; it does not touch the inner Bazel work that sets feedback time. Collection, policy, measurement limits and reproducibility
  • GitHub: 3,871 workflow runs across thirteen 2-hour created-time windows (each <1,000 results), 1,513 core runs, 4,565 core job attempts (all attempts, all conclusions), 123 open PR heads' latest check runs. Collection 20:54–21:02 UTC; a sweep, not an atomic snapshot. The stock evidence.sh recipes ran as supporting data.
  • BuildBuddy: deterministic invocation IDs (devinfra/ci/invocation_ids.py) resolved 66/66 completed devel attempts (tested SHA = push head, zero mismatches) and 225 of 582 PR/fork attempts (the rest skipped or were cancelled before an invocation existed). Target history for eight labels since 27 October; fresh executions = first appearance of a (duration, status) pair, cache hits repeat it exactly. Phase traces from undeclared outputs (k3s-timeline.jsonl, vm-phases.jsonl, junit test.xml, cert-manager logs) of the named invocations.
  • Live devel ruleset: required contexts Build artifacts + imports check, Pre-commit checks, bazel-ci / Test & Build; 0 required approvals; not strict up-to-date; linear history; extra approval for unattributed changes. CodeQL default setup not configured. Unchanged since the previous report.
  • Classes use first match on changed paths (docs-only → system tests → cdk8s → build/CI → frontend → Agentplane backend → other infrastructure → other code); superseded heads whose commits left the PR cannot be classified and are reported as unknown. Percentiles are nearest-rank, seconds, one-second GitHub resolution, uncalibrated cross-host skew.
  • Not measured this run: status publication, webhook delivery, inbox admission or agent receipt clocks; full auto-merge eligibility; Shapley attribution. No workflow, ruleset, scanning or Bazel policy was changed; the only experiments are read-only log/profile inspections.
  • Raw payloads, logs, profiles and worker identities stay local; the evidence file holds reviewed aggregates, invocation IDs and tested SHAs.

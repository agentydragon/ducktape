A retained-node heartbeat explains a separate minute-scale launch gate.

In the observer trial, all three VMs and launcher Pods were created immediately at 15:01:24–25 UTC, but the scheduler refused their node affinity. The retained node had kubevirt.io/schedulable=false and heartbeat 14:55:05; a 15:00:17 NodeUnresponsive event says the handler was not responsive. Provisioning only began15:02:18, then the Pods scheduled15:02:22–23. The same control path provisioned in 3–4s and scheduled 4–6s after the readiness wait began. The extra roughly 54s is before guest execution.

The pinned KubeVirt v1.8.2 source requires kubevirt.io/schedulable=true in its launcher selector. Its node controller marks a heartbeat older than 5 minutes unresponsive. The handler checks immediately on process start, then refreshes on a hardcoded 1 minute interval with jitter, 60–132s between checks. A restored snapshot can carry an old heartbeat into that gap. The endpoint snapshots differ only in schedulability; they do not exclude unrecorded transient label changes, but the observed false value is already a sufficient affinity failure.

A separate bounded candidate restarts only the DaemonSet-owned handler Pod on a clean warm baseline with no VM guests, then waits for the real producer to restore eligibility. It preserves operator ownership, labels, heartbeat data and safety thresholds. Validation includes restart/setup cost and an aged-baseline comparison; no latency saving is claimed before that experiment finishes.

What changed after the improvements

Added coverage now runs inside ordinary VM startup

runner_start synchronously executes all 11 real-systemd kernel subtests before exec agentplane-runner. All three VM scenarios boot independently. Six consoles show 47.79/25.56/69.91s and 29.99/28.97/26.83s spent on that proof: 143.26s and 85.79s per suite. It landed with #12503. In one boot, fixture service starts 19:08:36Z, passes at 19:09:25Z, real runner logs at 19:09:26Z and Ready is observed 19:09:27Z. This is directly observed serial work, not a queue inference.

The whole VM increase cannot be assigned to that change: fixture stack Ready also varied 265.5→122.8s, and images/source differ. Current three Ready spans total 366.123s / 308.222s, cleanup about 58s; both retain Claude, Codex and OOM cases. Earlier fast-readiness and exporter phase results remain valid under their original controls.

The Go race sweep repeats tests already configured for race detection

bazel_ci.py runs ordinary test, build, then a global-race Go test command. Actual race tails are 81–170s in selected jobs. The flag change discards analysis cache. A source-pinned query found 15 go_test(race="on") labels; runner_test is already linked with -race in the main invocation, then runs again in the global-race phase. Pinned rules_go v0.63.0 transition code confirms the per-target setting. Removing these duplicates preserves their main-gate race coverage; it does not remove the entire second command.

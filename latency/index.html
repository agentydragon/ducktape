Reproducibility and limits.

The collector verified 2,672 arriving workflow records against all API totals, recursively splitting the dense 30 October slice. It fetched 1,122 selected core run records and 3,371 job rows across attempts; these sums include repeated older-active sweeps. They are not unique PR counts. Visual job pages were separately collected for the busy and latest slices. Each core collection’s bounds and pagination counts are in evidence.

Required devel contexts were re-read live: Build artifacts + imports check, Pre-commit checks, bazel-ci / Test & Build. Rules require zero ordinary approvals, no code-owner review and no strict current-base condition, with an extra unattributed-change approval exception. CodeQL default setup is not-configured. Draft, conflicts, applicable exceptions, auto-merge enablement and historical review state are not reconstructed. Therefore no head is assigned a full auto-merge-readiness timestamp.

Each 90-minute slice is a complete arrival census, but the four slices are a fixed, nonrandom sample of a wider period. Closed/superseded heads retain unknown path class unless their exact final SHA matches current PR metadata. No head falls within 30 seconds of a lower window bound; incomplete companion gates remain non-green. Rerun attempts are joined to their original exact SHA. Two agent-fork heads were joined by full SHA and PR number to their frozen trusted-workflow titles: #13375 reached all three jobs in 226 seconds, #13376 in 455. Both are green; external forks requiring environment review have no sampled observations. Source normalization only makes those explicitly matched trusted events eligible for the same-head gate join.

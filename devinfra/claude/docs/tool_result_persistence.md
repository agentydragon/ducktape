# Claude Code Tool Result Persistence

How Claude Code handles tool results that exceed size limits. Based on source
from `claude-code-leaked` v2.1.88.

## Size Budget Tiers

Three independent limits, evaluated in order:

| Tier                  | Limit                                     | Scope                        |
| --------------------- | ----------------------------------------- | ---------------------------- |
| Per-tool              | `min(tool.maxResultSizeChars, 50K chars)` | Single tool result           |
| Global byte cap       | 400KB (`100K tokens × 4 bytes`)           | Single tool result           |
| Per-message aggregate | 200K chars                                | All tool results in one turn |

### Per-tool threshold

Each tool declares `maxResultSizeChars`. `getPersistenceThreshold()` caps it at
`DEFAULT_MAX_RESULT_SIZE_CHARS = 50_000`:

```typescript
return Math.min(declaredMaxResultSizeChars, DEFAULT_MAX_RESULT_SIZE_CHARS);
```

Notable tool limits:

| Tool         | Declared limit | Effective limit        |
| ------------ | -------------- | ---------------------- |
| MCPTool      | 100K           | 50K (capped)           |
| GrepTool     | 20K            | 20K                    |
| FileReadTool | `Infinity`     | exempt (circular read) |
| BashTool     | 20K            | 20K                    |
| Most others  | 100K           | 50K (capped)           |

A GrowthBook feature flag (`tengu_satin_quoll`) can override per-tool thresholds
at runtime.

### Per-message aggregate budget

When N parallel tool results land in one user message and their combined size
exceeds 200K chars, the **largest fresh results** are persisted until the total
is under budget. Each message is evaluated independently — 150K in turn 1 and
150K in turn 2 are both fine.

Controlled by `MAX_TOOL_RESULTS_PER_MESSAGE_CHARS`, overridable via GrowthBook
flag `tengu_hawthorn_window`.

## Persistence Flow

When a result exceeds the threshold (`maybePersistLargeToolResult`):

1. **Save full output** to
   `~/.claude/projects/<project>/<session>/tool-results/<tool_use_id>.{txt,json}`
2. **Replace content** sent to the model with a preview message:

```
<persisted-output>
Output too large (125.3 KB). Full output saved to: /path/to/tool-results/abc123.txt

Preview (first 2.0 KB):
[first ~2000 bytes, truncated at newline boundary]
...
</persisted-output>
```

3. The model is instructed to use **Read** (with `offset`/`limit`), **Grep**, or
   **jq** to access the full content in chunks.

The preview is generated by `generatePreview()` which takes the first
`PREVIEW_SIZE_BYTES = 2000` bytes, preferring to cut at a newline boundary
(falls back to exact cut if no newline in the last 50% of the preview).

## Replacement State & Cache Stability

Replacement decisions are tracked per `tool_use_id` in a
`ContentReplacementState`:

```typescript
type ContentReplacementState = {
  seenIds: Set<string>; // all results that passed through budget check
  replacements: Map<string, string>; // persisted results → exact preview string
};
```

Once a result's fate is decided (persisted or not), it is **frozen for the
conversation**. On subsequent turns, previously-replaced results get the cached
preview string re-applied (zero I/O, byte-identical). This preserves **prompt
cache prefix stability** — the same bytes appear in the same positions across
turns.

Lifecycle: one instance per conversation thread. Main thread never resets (stale
entries after `/clear` or rewind are harmless — tool_use_ids are UUIDs).
Subagents clone the parent's state for cache-sharing.

## Special Cases

### Empty results

Empty tool results (null, `""`, whitespace, `content:[]`) are replaced with:

```
(toolName completed with no output)
```

This prevents a model bug (`inc-4586`) where empty `tool_result` content causes
some models to emit the `\n\nHuman:` stop sequence and end their turn with zero
output.

### Image content

Tool results containing image blocks bypass persistence entirely — images must
be sent as-is to the model.

### Binary MCP content

Binary content (PDFs, XLSX, etc.) detected via `isBinaryContentType()` is saved
with a mime-derived extension via `persistBinaryContent()`. The model receives a
short message with the file path and can use Read to inspect it.

### FileReadTool exemption

`FileReadTool` has `maxResultSizeChars: Infinity` — it is exempt from
persistence. Persisting its output to a file that the model reads back with Read
would be circular.

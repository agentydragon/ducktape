## Dependency: `github.com/mark3labs/mcp-go` v0.37.0 -> **v0.54.1**

Two independent bounds pin it exactly.

### Lower bound: >= v0.54.1

`nwTZT_5` contains **two** types with `GetClientInfo` / `SetClientInfo` /
`GetClientCapabilities` / `SetClientCapabilities`:

```text
nwTZT_5.(*li36ir_).GetClientInfo      0x16c0f80   real body (atomic.Value load + type assert)
nwTZT_5.(*oZNTzbsSm).GetClientInfo    0x17676a0   <autogenerated>   (promotion wrapper)
```

mcp-go v0.54.1 introduced `server/client_info_store.go`, moving those four
methods onto an unexported `clientInfoStore` that each concrete session type

an `<autogenerated>` promotion wrapper on the outer type. In v0.54.0 the four
methods are declared directly on `*streamableHttpSession`
(`streamable_http.go:1379..1401`), which produces no wrapper.

## OAuth 2.0 protected-resource metadata

The RFC 9728 fields — `resource`, `authorization_servers`, `scopes_supported`,
`bearer_methods_supported`, `resource_name`, `resource_documentation`,
`resource_policy_uri`, `resource_tos_uri`, `jwks_uri`,
`resource_signing_alg_values_supported`,
`tls_client_certificate_bound_access_tokens`,
`authorization_details_types_supported`, `dpop_signing_alg_values_supported`,
`dpop_bound_access_tokens_required` — are **mcp-go's**
`server.ProtectedResourceMetadataConfig` (`server/protected_resource.go:26-78`),
introduced in mcp-go v0.51.0. They are the struct tags of the JSON document
served at `/.well-known/oauth-protected-resource`, which mcp-go mounts when a
transport is configured with `WithProtectedResourceMetadata` /
`WithSSEProtectedResourceMetadata`.

So they belong to the **MCP authorization flow** (the client-side discovery step
of <https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization>),
not to environment-manager's own auth. This package's servers still authenticate
with a locally generated `Bearer` token (`BaseServer.Start` -> `Start.func10`),
not OAuth.

**Undetermined:** whether environment-manager actually _enables_ the metadata
endpoint. The tags are present because the type descriptor is reachable through
`StreamableHTTPServer`'s field graph, which the linker retains regardless of
whether `WithProtectedResourceMetadata` is called; and
`BaseServer.Start` (0x17707a0) passes only two option closures whose payloads
are garble-encrypted. Both `CORSConfig` methods are linked
(`nwTZT_5.(*A0kcG8).vTjBUbo1PXBH` xrefs `Vary`/`Origin`;
`…vaMjsdU` xrefs `OPTI`), which is consistent with — but not proof of — the
metadata handler being mounted.

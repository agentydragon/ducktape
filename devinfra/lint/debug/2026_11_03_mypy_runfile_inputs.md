# Mypy runfile inputs

`rules_mypy` originally added each dependency's complete `default_runfiles.files` to every mypy action and used those files to discover generated import roots. The first patch retained named first-party Python files and all opaque directories while filtering unrelated first-party runtime files. A follow-up narrows first-party directory inputs using rules_python `PyInfo.transitive_original_sources`: a non-empty source set identifies declared directory artifacts to retain, while a missing, `None`, or empty field falls back to keeping every directory. The filtered files still retain all unowned/external runfiles, including wheels, plugins, native modules, and package data. Named `.py`, `.pyi`, and `py.typed` files, generated `direct_pyi_files`, and explicit `PyTypeLibraryInfo.directory` inputs remain available; the type-library directory is also added to MYPYPATH.

The follow-up was checked with a temporary Bazel fixture containing a generated Python source tree, a runtime-only tree, and an unknown custom PyInfo with an empty `transitive_original_sources` field. Fixture aquery invocation `6593d05e-930e-4722-89ca-f82828e5762c` showed the generated source tree and unknown-provider tree in the mypy action inputs, with the runtime-only tree absent. A positive RBE build passed (`1fe95321-b748-4aff-a61a-ab342a44e33f`). Changing the consumer return type to `str` failed with mypy `[return-value]` because the generated function returns `int` (`f3963cd4-ac65-467e-ab54-d22a1f56286f`). The temporary fixture and negative probe were removed after validation.

On the production `//agentplane/app:test_live` action, aquery invocation `2c379672-5907-43cc-aef4-54c2c0ab2cb6` shows the first-party `agentplane/app/frontend/serving/static_image` OCI tree is absent. The action retains generated `.pyi` stubs including `egress_admin_pb2.pyi`, `py.typed` markers, and both configured plugin modules (`pydantic/mypy.py` and `sqlalchemy/ext/mypy/plugin.py`). The external `envtest` runtime tools remain because external-owned runfiles are deliberately preserved. The production mypy targets `//agentplane/app:test_live` and `//agentplane/env/e2e/testing:failure_journal` both passed on base `4dff4e5daf151db9609b0cfadd0eb50599f45515` in invocation `1cdbf6a7-0f4d-4690-94bb-fc1cb92c2305`.

The fixture build and negative probe ran on base `d24f6f09df178b476d6becf215e6be054bcdcc4a`. Before committing, the branch was rebased onto `origin/devel` at `e203f853481697c157c539738874ed87da161743`. The production build and aquery ran after rebasing to `4dff4e5daf151db9609b0cfadd0eb50599f45515`, which included changes to `agentplane/app/test_live.py` and its BUILD dependencies. The only later base change was a staging image-pin update under `cluster/`, outside the checked target closure. No fixture or patch logic changed during either rebase.

This validates the action graph and typing behavior; no performance claim is made. The filter treats a non-empty `transitive_original_sources` set as complete metadata. Empty, absent, or `None` metadata uses the conservative all-directory fallback; a custom provider that supplies a non-empty but incomplete set was not present in the fixture.

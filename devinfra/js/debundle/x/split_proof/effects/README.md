# Footprints by abstract interpretation

[`Effects.lean`](../lean/EsmSplit/Effects.lean) reads the code: it runs the bundle's top level once over abstract values and reports, per unit, whether it touches the world (`effect`), which names it may change (`writes`) and which names it reads through functions it calls (`deps`). [`Lower.lean`](../lean/EsmSplit/Lower.lean) adds what the unit declares, mentions and assigns. `lower`, `translate` and `lowersplit` all use it; there is no other classification of units. The checker's trust is in the interpreter's rules and in the premises below. Both are tested against Node, neither is proved.

## Run

```bash
cd ../lean && lake build lower translate split_preview
cd ../translation && cp package.json.in package.json && npm ci --no-audit --no-fund
node ../effects/run.mjs [--show]                      # golden cases
node ../effects/run.mjs --permutations 20 --seed 1    # and random permutations of every case's units
node fuzz.mjs --count 300 --seed 3                    # tree fuzzer
node frontend.mjs bundle <bundle.js> --out bundle.json
../lean/.lake/build/bin/lower bundle.json --premises premises.json              # a footprint per unit, as JSON lines
../lean/.lake/build/bin/translate bundle.json output.json cert.json --premises premises.json [--table t.json]
jq '{entry, chunks:[{path:.entry, source:"ast.json", spec:"spec.json"}]}' spec.json > deployment.json
../lean/.lake/build/bin/split_preview deployment.json outdir [--premises premises.json | --footprints footprints.jsonl] [--plan plan.json]
```

This is a diagnostic invocation. Plan output and any emitted files are uncertified previews, even when the structural checks pass.

`effects:effects_cases_test` and `translation:fixtures_test` run the golden cases and fixtures in Bazel. `split_preview --footprints` reads what `lower` printed instead of analyzing again: the analysis does not depend on the split, so a run of many splits of one big bundle computes it once.

Run the generated Effects matrix with `bbr test //devinfra/js/debundle/x/split_proof/effects:effects_targeted_fuzz_test`. The CI run uses seed `20261121` and checks the named reorders, including stdout-changing reorders for uncaught throws. Append `--test_arg=--seed --test_arg=77` for another seed or `--test_arg=--permutations --test_arg=3` to sample random reorders. When `CASES` is relative, `run.mjs` resolves it from its own directory.

## Premises

Printed with every verdict (`premiseLines`), assumed and not checked:

| #   | Premise                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | Nothing the analysis cannot see patches the intrinsics (`Object`, `Array`, `Function`, `Promise`, …). What it sees: a store, a definition, a deletion, a change of prototype or an accessor defined on an intrinsic reached by name or through a prototype chain, in code it runs; and in code it does not run (a generator body, a call it did not follow, a callback of a function it has no row for, a `Proxy` trap, a unit it gave up on) as far as the text names the intrinsic (`Object.prototype.x = …`, `Object.defineProperty(Array.prototype, …)`, `Math.max = …`, `Array = …`, `globalThis.Promise = …`). A change to a static member makes the units that read the member effects that run unknown code; any other change makes every unit that is not a function declaration one. Not seen: a patch through an alias or a computed name in code it does not run, a standard function forwarded through a spread or called through a computed name, a global defined with `Object.defineProperty(globalThis, …)`, a patch by another script, one through a value the world returned, and state the engine keeps (`RegExp.$1`): [`debug/p1_known_gaps`](debug/p1_known_gaps/README.md) has a program for each. |
| P3  | The world defines no hooks: it adds no accessor or conversion hook to an object the program made (accessors and hooks the program defined are run). `noWorldHooks` in the premises file; **off by default**: reading, assigning or converting an object the world holds is then a call into the world. The premise is about objects the analysis follows. A value the world made (what a call into the world returns, an import) is not one: every operation on it is unknown code, with or without the premise (see below). Assumed and not seen: code of the program that is not run here (a callback the world runs, a generator body), or a standard function without a row, adds an accessor or a hook to an object the world holds: [finding F7](../translation/debug/generator_findings/README.md). Production bundles do this, so P3 is not set for real inputs; the cases and fuzzers set it to test the analysis under it.                                                                                                                                                                                                                                                                                      |
| P4  | Evaluation completes: no exception that the language raises itself in code that is otherwise pure (a property of `undefined`, a name in its dead zone, a call of something that is not a function), no hang (premise A6 of [`design.md`](../../../docs/design.md)). A `throw` statement is not under this premise: one that the analysis reaches outside every `try` with a `catch` makes its unit unknown code, also inside a function the unit calls. For the rest, the equivalence claimed is for runs that complete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| P5  | No other chunk runs during evaluation, except through callbacks this chunk gave the world.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| V   | The vendor table: imports from outside the tree that only allocate (`"./v.js#make": "kit"`), and per family the members that only allocate. Any other import is the world.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

The premises file is `{"vendor": {"from#imported": "family"}, "members": {"family": ["m"]}, "noWorldHooks": true}`. Every key is optional; an unknown key or a wrong shape is an error. A table written to make a measurement come out well is a guess: label it as one.

The list of members the standard objects have comes from the Node that ran [`gen_members.mjs`](gen_members.mjs) (`IntrinsicMembers.lean`, with the version in its header). A member of a newer ECMAScript is missing from it: regenerate when Node moves on.

## What it computes

- Values: a set of codes (some primitive, the world, or an allocation site qualified by the call chain that reached it). Objects have constant-key properties, a bucket for other keys, prototypes and the keys with accessors. Variables and function scopes are objects too. Updates only add, so one pass in order summarizes the state before each unit under every valid order.
- Calls into code it can see are run (inlined; one level of call-site context, a depth cap, a step budget per unit, memoized while the heap is unchanged). Bound functions and the calls a standard function makes count as a level of the call chain. Intrinsics come from the table in [`Intrinsics.lean`](../lean/EsmSplit/Intrinsics.lean) (data, with the reason each row is safe). Any other call is the world.
- A call into the world makes the unit an effect; every object passed in **escapes**: the world may mutate it and call any function reachable from it. What the world returns is one value, _the world's_. It may be a `Proxy` with a handler of the program, an object of the program that came back with its getters, or an instance the world made of a class of the program, so a read of a property of it, a conversion of it and a query of it (`in`, `instanceof`, `for…in`, a standard function that is given it, `await`) are unknown code; so are a read, a store and a conversion of an object that inherits from it. `typeof`, `===` and a truth test are free. Variables those functions assign are _tainted_ (reads may return anything). A unit that runs code the analysis cannot see writes every name that reaches an escaped object; a unit that only talks to the environment (`console.log`, `addEventListener` with a callback it keeps) writes none.
- `writes` are names: every module-scope name from which a changed object can be reached. `deps` are names read by code the unit ran but did not mention (closures reached through objects other units filled).
- Names the bundle exports start out escaped: another module may call an exported function, or read an exported binding, while this one evaluates (a cycle). Lean reads the module’s import and export declarations from its annotated ESTree. In the source-ordinal view used by `lowersplit`, an import occupies a unit and executes as an empty statement. Translation certificates number body units and track imports separately.
- Code that runs without a call expression is run or given up on the same way: a getter or setter (own or inherited), a conversion hook (`valueOf`, `toString`, `Symbol.toPrimitive`), the iterator of a spread or a `for…of`, a `then` of a thenable, a generator body (it runs when the iterator is advanced, in some later unit), and the conversions the standard functions do on their arguments. `await` makes the unit an effect: the continuation runs after the program, in the order the awaits were reached.

**Fail safe.** An unrecognized node, a direct `eval`, an exhausted budget or an over-wide set becomes a call into the world that also escapes everything the unit mentions. A call that is run but not looked into (deeper than the depth cap, through more candidates than the fan-out cap, a generator) escapes the function and its closure, and the text of code that is not run is read for patches of intrinsics by name (premise P1). More precision comes from understanding a construct. A wrong understanding gives a wrong verdict, and so does a give-up that forgets what the code it skipped can reach.

## Cost

On the large production bundle (private, 9,707 units): 114 s for the analysis, 318,332 abstract objects, 1.45 GB peak for the whole `translate` run. 135 units run out of the 100,000-step budget and become unknown code. `zod` (1,072 units) takes 200 to 350 s depending on the load, minified 60 to 70 s; where the time goes is not profiled (`TODO.md`). A split of one big bundle should be analyzed once: `split_preview --footprints` reads what `lower` printed. Bazel's `lean_binary` runs the Lean interpreter, about ten times slower than the native build, so the Bazel tests use small inputs.

## Tests

- `effects_known_gaps_test` runs the documented intrinsic-summary, P1 and P3 cases through `translate` and Node. Each listed reorder must still be accepted and print different output with both programs completing. The P3 cases must also be refused with P3 off. If a checker change refuses a listed reorder under its original premises, move the case into the regular regression suite.

- [`targeted.mjs`](targeted.mjs): a seed-driven matrix for iterator-helper consumers, prototype and `flat(Infinity)` depth boundaries, bounded recursive hooks, and uncaught throws. It asserts unit classifications and requires a stdout-changing Node reorder for every family; `translate` must not accept those reorders. Non-throw cases also include an accepted reorder with unchanged output. Bazel runs it as `effects_targeted_fuzz_test` with seed `20261121`.

- `reflective_receivers_test` and `reflective_receivers_second_seed_test` compose a call through `Reflect.get` or `Reflect.set` with data properties or accessors, own or inherited lookup, explicit or default receivers, and seeded aliases and call forms. Each program runs an accepted control and a stdout-changing reorder through `translate` and Node.

- [`cases.mjs`](cases.mjs): 110 small bundles with the classification of every unit (`world`, `pure`, `writes a b`, `world writes a b`), each checked against what JavaScript does, and 91 reordered programs run in Node next to the original (90 print something else; `run.mjs` requires the checker to refuse those). [`cases_general.mjs`](cases_general.mjs): 180 more, each one reordered program (177 that Node prints differently, and three that it prints the same and `translate` must accept), for the general rules (callbacks, the shapes standard functions return, spreads, computed keys, iterators, protocol methods) and for the core language (the call memo, classes, parameter scope, `switch`, closures at one site, optional chains). Two fresh agents found 88 of them as wrong accepts of earlier versions, and the three they found that still are one are in [`debug/general_known_gaps`](debug/general_known_gaps/README.md). The generators and the footprint oracle of [`../translation`](../translation/README.md#the-generator-of-the-whole-language) found 20 more (findings F1 to F6 there), a review of the same causes found 58 siblings, and the mutation harness asked for 4 more; all but two set premise P3, as the fuzzers do. Five are for the `throw` rule. `--permutations N` adds random permutations of every case's units. A `pure` where the code writes something is a bug; a `world` where the code is harmless is a loss of precision. CI runs the classifications, original Node exit checks, and handwritten reorders in `effects_cases_test`. Run `bbr test //devinfra/js/debundle/x/split_proof/effects:effects_permutations_test` explicitly to add three random permutations per normally completing case.
- [`fuzz.mjs`](../translation/fuzz.mjs): random bundles and splits, Node as the oracle (`fuzz_test`, `fuzz_leaks_test`, the corpora of [the translation README](../translation/README.md#fuzzer)). Templates that need this analysis: aliases through a variable, a destructuring or a registry object, writes through a helper, closures with state, instances, decorators and getters.
- [`lower_exports_test.mjs`](../translation/lower_exports_test.mjs): `lower` and `lowersplit` hold the names an ESTree dump exports for the world, and agree on how many units touch it.
- The existing suites of the project run on it: the fixtures, the emission tests, the Shift grammar fuzzers (about 5,500 random programs in a larger run, none accepted wrongly) and [the real-bundle splits](../experiments/README.md#7-real-splits-halves-cuts-blocks-random-placements).
- [`fuzz_mutate.py`](../translation/fuzz_mutate.py): 155 mutants, each removing one rule of the analysis (or of the model); `run.mjs` runs first, then the fuzzer. A mutant that neither catches is either harmless or a missing case. Last run: 144 caught by a case or the fuzzer, 4 by a proof that stops building, and 7 survive. Two of those are harmless: `no Hygienic`, which the link check makes redundant, and `nested hooks are unbounded`, where the step budget ends the recursion and the unit gives up. Five survived before the fixes of F1 to F6 too and are not looked into: `a replayed call drops what it threw`, `memoized calls replay no writes`, `an unseen constructor does not escape`, `Intl reads no options` and `Error reads no options`. Survivors found missing cases eight times (module reads, premise P3 off, `catch` and `finally`, `__defineGetter__` on a program object, a pure reader after a long prototype chain, a binding of another module, the result of a `reduce` callback, a later source of `Object.assign`) and two equivalent mutants, whose dead code is deleted.

## Finding what blocks precision

`EFFECTS_WHY=1 ../lean/.lake/build/bin/lower bundle.json --premises p.json` prints, on stderr, how many units touch the world for each first reason (`call of import ./vendor.js#o`, `getter or setter the world made`, `store into env:window`, …) with four unit numbers each. The reasons that name an import are the vendor table's work list.

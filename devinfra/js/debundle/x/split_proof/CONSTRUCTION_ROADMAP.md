# Build order for the CoreJS splitter

The deliverable is the production CLI splitting a pinned application according to its **unchanged authored placement**. Count an extraction only when the compiled constructor accepts it and the CLI writes its modules. Start with one dependency-closed region, then two interacting regions, then their union, before claiming the whole application. If the placement actually changes behavior, a refusal with a small counterexample is the correct result.

The [contract and evidence ledger](PLAN.md#acceptance-contract) distinguishes the theorem from its application. The JS frontend, scope annotation/lowering and JS printer are trusted. Lean proves the transformation **between CoreJS programs** at splitter build time. For every source and placement the constructor accepts, its output must honor ownership and module order, preserve public names and live cells, and preserve all modeled outcomes, effects and final state in every admitted world. Matching normal returns misses a write followed by a throw. Matching two `unknown` results does not establish how an unmodeled host operation behaves. Keep such a case outside the claimed coverage unless a rule establishes preservation without needing to interpret that operation.

## Lean representation and proof interfaces

Reuse [CoreJS syntax](lean/EsmSplit/CoreJS/Syntax.lean), [live addresses, state and outcomes](lean/EsmSplit/CoreJS/Value.lean), [the authored spec and planner](lean/EsmSplit/Plan.lean) and [linked execution](lean/EsmSplit/CoreJS/LinkedBehavior.lean). The following are proposed interfaces; they need not become new types if an existing type states the invariant.

| Interface                     | Information it must retain                                                                                                                                                                 | Obligation on its producer                                                                                                                                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Indexed source                | Source module plus original ordinal for every selectable unit; distinguish executable declarations from import/export metadata. Retain binding origin independently of its local spelling. | Projection back to the executable body and export table agrees with the input. Never renumber around a non-executable export and silently change what a selector means.                                                                      |
| Resolved placement            | Map original units to requested owners, residual entry, requested order and external module surface.                                                                                       | Each unit has exactly one allowed owner. Reject unknown or conflicting claims; preserve publicly visible aliases and metadata placement.                                                                                                     |
| Linked plan                   | Static dependency edges in evaluation order, import/re-export bindings, declaration instantiation, environments mapping names to cells, executable schedule.                               | Show from source and plan why generated edges resolve to the right **cell**, including aliases. Two bindings with equal initial values need not be aliases. Preserve TDZ, initialization once, and live updates.                             |
| Admitted operation            | An order-preserving boundary or a permitted local move, with decidable source/plan preconditions.                                                                                          | Each rule proves placement, linkage and behavior of the graph it constructs. Compose the rules by induction. If a future representation changes addresses, prove a consistent identity/alias relation, not just equality of exported values. |
| Runtime and host observations | Use the existing world, state and bounded outcomes. The thin runtime interface is `construct(source, resolvedSpec) → output | refusal`. The trusted printer receives that output; staging, file-set/readback checks and atomic publication guard the IO path. A recheck identifies that particular constructed artifact. None of these checks substitutes for the transformation theorem.

## Vertical slices and dependencies

Each row needs a named theorem about a family, a positive ordinary CLI fixture under the authored spec, a discriminating negative, and a focused build/test. A model lemma, a fixture passing under Node, and acceptance by the CLI are three distinct results.

Async execution and dynamic loading have separate design gates below. They need not delay a static region whose semantics are already covered. Conversely, a whole-program claim cannot ignore a reachable unsupported feature.

### Which language features to buy with a new rule

Measure these against whole requested regions. A syntax node appearing in a deferred body, a declaration evaluated while linking, and an expression reached during initialization impose different obligations.

- **Declarations and patterns:** start with `const` and earlier reads. Track `let` writes, hoisted/repeated `var`, multi-declarator ordinals, shadowing and closures over mutable cells. Object patterns can invoke getters in order; array patterns can invoke or close an iterator. Use a default that throws to distinguish the order of partial effects.
- **Functions and classes:** distinguish creating a callable from calling it. Track recursive captures, method receivers, parameter defaults and `arguments`. Evaluating class heritage, computed keys, static fields or a static block can call user code even if nobody constructs an instance. Extend one measured family at a time.
- **Expressions and heap:** short-circuiting, optional chaining, coercion, property descriptors and aliases can change which effects run. Introduce read/write/allocation summaries only where their soundness is proved for the admitted expression. Test a getter that mutates the next binding; do not classify a read by syntax alone.
- **Open environments:** unresolved callbacks, `eval`, ambient mutation and reflection may defeat a local summary. Keep the region together or refuse unless an explicit rule establishes its footprint and observable behavior. Record this separately from a frontend that simply cannot represent a feature yet.

## Observable boundaries and refusal policy

| Boundary                                 | First useful case                                                                                                                                                                                           | What can invalidate it; how to tell                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stacks, URLs and reflection              | Retain source-sensitive code at its original site when that suffices.                                                                                                                                       | `Error.stack` can expose the moved frame, caller URL, line or column; `import.meta.url` changes relative resolution. Use a same-entry-URL negative with an exported stack or a stack-derived key. Source maps or equal thrown error names do not make the strings equal.                                                                                                                                                                                                        |
| Functions and classes                    | Move a closure only with preserved captures, identity and observable representation.                                                                                                                        | `Function.prototype.toString.call(f)` can expose changes in spelling, comments and whitespace; `name`, `length`, prototypes, `this`, `super` and class static effects can also matter. Check a public alias, call after mutation, and stringify the callable. If a rule relies on preserving a source slice, specify what the trusted printer must retain. Otherwise pin or refuse.                                                                                             |
| Imports and host resolution              | Closed, statically resolved relative graph under the existing deployment contract.                                                                                                                          | Cycles, mutable exports, namespace identity, resolution relative to the importer and error timing matter. Bare specifiers, import maps, failable/dynamic requests, module cache identity and `import.meta` require an explicit supported environment. A literal `import()` still returns a promise. Do not introduce an import map, resolver or loader on the user's behalf.                                                                                                    |
| Async functions, promises and generators | Count definitions, calls during initialization, escaping callables and actual suspension separately. Defining a function does not run its body; invoking an async function does run its synchronous prefix. | Model promise identity, rejection vs. synchronous throw, thenable getters, job order and resumption before admitting reached `await`. Generators start/resume via their iterator. Top-level await also changes dependent module evaluation and cycles. Require the same observable traces under a stated host/job schedule; test a microtask racing an export update, rejection/finally, and an awaiting import cycle. Until those semantics exist, refuse affected placements. |
| Heap and host effects                    | Admit only accesses justified by the operation's rule.                                                                                                                                                      | A property read may invoke a getter or proxy; allocation order, symbols, object identity, realm intrinsics and host reads may escape. Start with ordinary data; use a getter that writes or throws and a pair of aliased objects as controls. Unknown host behavior is a blocker, not permission to assume purity.                                                                                                                                                              |

Changing the contract (for example ignoring stack strings), adding a host premise or designing a loader is an owner decision. First bring a concrete observable difference, the placements affected, and an alternative that keeps the existing contract.

## Evidence and project management

- Treat historical tests as requirements discovery. The [stack fixture](translation/test_stack_location.py), [async methods](translation/linked/async_methods_test.mjs), [generator tests](translation/linked/generator_test.mjs), and [browser import/metadata cases](integration/excalidraw/browser_smoke_test.py) identify observations. Earlier certificates and preview runs do not count as coverage of the new constructor.
- Use the [historical production survey](PLAN.md#production-replay-status) for prioritization, with its date, revision and denominator. An older isolated-unit survey accepted 3,210 of 8,082 selected units **at lowering**; 1,294 first refusals concerned identifier/pattern shape and 589 concerned async/generator functions. These are neither current constructor results nor counts of executed async calls.
- Measure the unchanged 16+16 case and the pinned scroll extraction separately. The former first refused at export ordinal 32. For the latter the observed CLI path restriction and the decoder's `Object` refusal precede the proof rule: [measured run](https://app.buildbuddy.io/invocation/b8544f7b-3cf6-4763-933a-38b99344a42c). Record whether the first blocker is selector/adapter, modeled operation, unsafe placement, host premise, artifact IO or resource budget. A timeout is not a semantic counterexample.
- Keep private source, owner names, selectors, paths and artifacts private. An authorized runner should record revision, count of requested/realized owners and units, first refusal by feature, whether code is reached during initialization, time and peak memory, and the original application's observable smoke result. Publish only approved aggregates or independently constructed generic controls.
- Work in parallel on **source IDs and link cells**, **order-preserving behavior and closure calls**, **safe moves**, **production fixtures**, and **host/async evidence**. The coordinator owns dependencies and promotion of results into the [acceptance ledger](PLAN.md). For each slice track owner, proof PR, integration PR, pinned input/spec revision, known negative, last actual CLI verdict, and next blocker. Mark it complete only after the integrated result passes. Prioritize features by newly unblocked complete requested regions and the first actual failure, not by syntax counts alone.

## Retirement gate

Delete per-input proof generation and compilation, generated-instance fixtures and freshness checks, finished-pair semantic replay as a publication route, weaker normal-completion/structural fallbacks, unchecked emitters, and their strategy switches and census-only machinery. Remove a test whose only assertion is that a retired route issues a particular certificate. Preserve an independent assertion about the original program, a scope/alias invariant, the parser, or a real browser observation in the component it tests. Do not produce an unproved split just to keep a fixture alive.

Verify deletion in the source **and** in the native target's configured dependency graph, runfiles, build/test targets, scripts and current usage docs. Keep the general CoreJS semantics, independently used proof lemmas and named axiom audits, the compiled constructor and its trusted adapters. A legacy module name is a lead to investigate: identify its last real consumer before deleting or extracting a lemma. Keep historical counterexamples with their limitations; retire instructions that suggest running obsolete paths.

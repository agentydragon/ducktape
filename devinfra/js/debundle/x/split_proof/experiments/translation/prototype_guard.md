# Prototype guard diagnostic

`prototype_guard.mjs` is a standalone syntactic experiment. It does not change the translation checker, create a proof, or discharge an ordering obligation. It accepts a deliberately narrow closed module with two statements: a non-derived local class and a `const` initialized by directly constructing that class with one object literal of primitive own data properties. The constructor must contain only assignments from those own argument properties to predeclared own instance fields. Static or computed elements, accessors, spreads, unknown calls, unsupported parameters and all other statements fall back.

The closed module restriction ensures the class binding is initialized at the call and no intervening source statement can reassign it. Own argument properties avoid inherited getters; predeclared instance fields are created before the constructor body and avoid inherited setters. Class fields and argument properties must have noncomputed names and no observable initializer. This is an intentionally conservative diagnostic about syntactic conditions, not a verified correspondence to ECMAScript or a full effect analysis. It does not analyze later calls, exports, module linking or transformed output.

`prototype_guard_test` tests a candidate in Node with a poisoned prototype and shows that deleting the argument's own property invokes an inherited getter, while deleting the instance field invokes an inherited setter. Unsupported calls and shapes are rejected by the diagnostic. Its Node runs are finite behavioral examples; the diagnostic has no Lean proof.

This restricted direct `new` pattern does not handle a local helper that calls constructors, and cannot infer facts across multiple source units. Its conditions therefore do not discharge any obligations in the current downstream Tana helper family. Extending it requires a real call graph, stable binding and prototype facts, effect-safe argument evaluation, and a proof bridge before it can affect acceptance.

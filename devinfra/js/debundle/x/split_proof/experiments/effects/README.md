# Footprints by abstract interpretation

[`Effects.lean`](../../lean/Experiments/Effects.lean) reads the code: it runs the bundle's top level once over abstract values and reports, per unit, whether it touches the world (`effect`), which names it may change (`writes`) and which names it reads through functions it calls (`deps`). [`Lower.lean`](../../lean/Experiments/Lower.lean) adds what the unit declares, mentions and assigns. `lower`, `translate` and `lowersplit` all use it; there is no other classification of units. The checker's trust is in the interpreter's rules and in the premises below. Both are tested against Node, neither is proved.

## Run

```bash
cd ../../lean && lake build lower translate lowersplit
cd ../experiments/translation && cp package.json.in package.json && npm ci --no-audit --no-fund
node ../effects/run.mjs [--show]                      # golden cases
node ../effects/run.mjs --permutations 20 --seed 1    # and random permutations of every case's units
node fuzz.mjs --count 300 --seed 3                    # tree fuzzer
node frontend.mjs bundle <bundle.js> --out bundle.json
../../lean/.lake/build/bin/lower bundle.json --premises premises.json              # a footprint per unit, as JSON lines
../../lean/.lake/build/bin/translate bundle.json output.json cert.json --premises premises.json [--table t.json]
../../lean/.lake/build/bin/lowersplit ast.json spec.json outdir [--premises premises.json | --footprints footprints.jsonl]
```

`./run.sh --translation` runs the golden cases and the fixtures. `lowersplit --footprints` reads what `lower` printed instead of analyzing again: the analysis does not depend on the split, so a run of many splits of one big bundle computes it once.

## Premises

Printed with every verdict (`premiseLines`), assumed and not checked:

| #   | Premise                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | Nothing the analysis cannot see patches the intrinsics (`Object`, `Array`, `Function`, `Promise`, …). What it sees: a store, a definition, a deletion, a change of prototype or an accessor defined on an intrinsic reached by name or through a prototype chain, in code it runs; and in code it does not run (a generator body, a call it did not follow, a callback of a function it has no row for, a `Proxy` trap, a unit it gave up on) as far as the text names the intrinsic (`Object.prototype.x = …`, `Object.defineProperty(Array.prototype, …)`, `Math.max = …`, `Array = …`, `globalThis.Promise = …`). A change to a static member makes the units that read the member effects that run unknown code; any other change makes every unit that is not a function declaration one. Not seen: a patch through an alias or a computed name in code it does not run, a standard function forwarded through a spread or called through a computed name, a global defined with `Object.defineProperty(globalThis, …)`, a patch by another script, one through a value the world returned, and state the engine keeps (`RegExp.$1`): [`debug/p1_known_gaps`](debug/p1_known_gaps/README.md) has a program for each. |
| P3  | The world defines no hooks: it adds no accessor or conversion hook to an object the program made, and converting a value the world made runs no program code (accessors and hooks the program defined are run). `noWorldHooks` in the premises file; **off by default**: every access to an object the world holds, and every conversion of a value the world made or holds, is then a call into the world.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| P4  | Evaluation completes: no uncaught exception, no hang (premise A6 of [`design.md`](../../../../docs/design.md)). A unit that merely might throw is not an effect for that reason; the equivalence claimed is for runs that complete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| P5  | No other chunk runs during evaluation, except through callbacks this chunk gave the world.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| V   | The vendor table: imports from outside the tree that only allocate (`"./v.js#make": "kit"`), and per family the members that only allocate. Any other import is the world.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

The premises file is `{"vendor": {"from#imported": "family"}, "members": {"family": ["m"]}, "noWorldHooks": true}`. Every key is optional; an unknown key or a wrong shape is an error. A table written to make a measurement come out well is a guess: label it as one.

The list of members the standard objects have comes from the Node that ran [`gen_members.mjs`](gen_members.mjs) (`IntrinsicMembers.lean`, with the version in its header). A member of a newer ECMAScript is missing from it: regenerate when Node moves on.

## What it computes

- Values: a set of codes (some primitive, the world, or an allocation site qualified by the call chain that reached it). Objects have constant-key properties, a bucket for other keys, prototypes and the keys with accessors. Variables and function scopes are objects too. Updates only add, so one pass in order summarizes the state before each unit under every valid order.
- Calls into code it can see are run (inlined; one level of call-site context, a depth cap, a step budget per unit, memoized while the heap is unchanged). Bound functions and the calls a standard function makes count as a level of the call chain. Intrinsics come from the table in [`Intrinsics.lean`](../../lean/Experiments/Intrinsics.lean) (data, with the reason each row is safe). Any other call is the world.
- A call into the world makes the unit an effect; every object passed in **escapes**: the world may mutate it and call any function reachable from it. Variables those functions assign are _tainted_ (reads may return anything). A unit that runs code the analysis cannot see writes every name that reaches an escaped object; a unit that only talks to the environment (`console.log`, `addEventListener` with a callback it keeps) writes none.
- `writes` are names: every module-scope name from which a changed object can be reached. `deps` are names read by code the unit ran but did not mention (closures reached through objects other units filled).
- Names the bundle exports start out escaped: another module may call an exported function, or read an exported binding, while this one evaluates (a cycle). The front end lists them; for an ESTree dump (`lowering/dump.mjs`) they come from its `export` statements, the same function (`Lower.exportedBindings`) for `lower` and `lowersplit`. The imports are listed by the front end too, or read from the dump's `import` statements (`Effects.importsOf`); in a dump an `import` statement is a unit that does nothing.
- Code that runs without a call expression is run or given up on the same way: a getter or setter (own or inherited), a conversion hook (`valueOf`, `toString`, `Symbol.toPrimitive`), the iterator of a spread or a `for…of`, a `then` of a thenable, a generator body (it runs when the iterator is advanced, in some later unit), and the conversions the standard functions do on their arguments. `await` makes the unit an effect: the continuation runs after the program, in the order the awaits were reached.

**Fail safe.** An unrecognized node, a direct `eval`, an exhausted budget or an over-wide set becomes a call into the world that also escapes everything the unit mentions. A call that is run but not looked into (deeper than the depth cap, through more candidates than the fan-out cap, a generator) escapes the function and its closure, and the text of code that is not run is read for patches of intrinsics by name (premise P1). More precision comes from understanding a construct. A wrong understanding gives a wrong verdict, and so does a give-up that forgets what the code it skipped can reach.

## Cost

On the large production bundle (private, 9,707 units): 114 s for the analysis, 318,332 abstract objects, 1.45 GB peak for the whole `translate` run. 135 units run out of the 100,000-step budget and become unknown code. `zod` (1,072 units) takes 200 to 350 s depending on the load, minified 60 to 70 s; where the time goes is not profiled (`TODO.md`). A split of one big bundle should be analyzed once: `lowersplit --footprints` reads what `lower` printed. Bazel's `lean_binary` runs the Lean interpreter, about ten times slower than the native build, so the Bazel tests use small inputs.

## Tests

- [`cases.mjs`](cases.mjs): 110 small bundles with the classification of every unit (`world`, `pure`, `writes a b`, `world writes a b`), each checked against what JavaScript does, and 91 reordered programs run in Node next to the original (90 print something else; `run.mjs` requires the checker to refuse those). [`cases_general.mjs`](cases_general.mjs): 133 more, each one reordered program (132 that Node prints differently, and one that it prints the same and `translate` must accept), for the general rules (callbacks, the shapes standard functions return, spreads, computed keys, iterators, protocol methods) and for the core language (the call memo, classes, parameter scope, `switch`, closures at one site, optional chains). Two fresh agents found 86 of them as wrong accepts of earlier versions, and the five they found that still are one are in [`debug/general_known_gaps`](debug/general_known_gaps/README.md). The generators and the footprint oracle of [`../translation`](../translation/README.md#the-generator-of-the-whole-language) found 42 more; those set premise P3, as the fuzzers do. `--permutations N` adds random permutations of every case's units. A `pure` where the code writes something is a bug; a `world` where the code is harmless is a loss of precision. CI runs them as `effects_cases_test` and `effects_permutations_test`.
- [`fuzz.mjs`](../translation/fuzz.mjs): random bundles and splits, Node as the oracle (`fuzz_test`, `fuzz_leaks_test`, the corpora of [the translation README](../translation/README.md#fuzzer)). Templates that need this analysis: aliases through a variable, a destructuring or a registry object, writes through a helper, closures with state, instances, decorators and getters.
- [`lower_exports_test.mjs`](../translation/lower_exports_test.mjs): `lower` and `lowersplit` hold the names an ESTree dump exports for the world, and agree on how many units touch it.
- The existing suites of the project run on it: the fixtures, the emission tests, the Shift grammar fuzzers (about 5,500 random programs in a larger run, none accepted wrongly) and [the real-bundle splits](../README.md#7-real-splits-halves-cuts-blocks-random-placements).
- [`fuzz_mutate.py`](../translation/fuzz_mutate.py): 71 mutants, each removing one rule of the analysis (or of the model); `run.mjs` runs first, then the fuzzer. A mutant that neither catches is either harmless or a missing case. Last run: 66 caught by a case or the fuzzer, 4 by a proof that stops building, and 1 survives, `no Hygienic`, which the link check makes redundant. Survivors found missing cases four times (module reads, premise P3 off, `catch` and `finally`, `__defineGetter__` on a program object) and an equivalent mutant, whose dead code is deleted.

## Finding what blocks precision

`EFFECTS_WHY=1 ../../lean/.lake/build/bin/lower bundle.json --premises p.json` prints, on stderr, how many units touch the world for each first reason (`call of import ./vendor.js#o`, `getter or setter the world made`, `store into env:window`, …) with four unit numbers each. The reasons that name an import are the vendor table's work list.

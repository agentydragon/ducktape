# Prototype guard diagnostic

`prototype_guard.mjs` is a standalone syntactic experiment. It does not change the translation checker, create a proof, or discharge an ordering obligation. It accepts a deliberately narrow closed module containing a non-derived local class, optionally a local helper, and a `const` initialized by constructing that class either directly or through the helper. The helper must take one parameter and do nothing except return the result of passing that parameter to the constructor. The call argument must be an object literal containing only primitive values or arrow-function values as own data properties. The constructor must contain only assignments from those own argument properties to predeclared own instance fields. Static or computed elements, accessors, spreads, unknown calls, unsupported parameters and all other statements fall back.

The closed module restriction ensures the class and helper bindings are initialized at the call and no intervening source statement can reassign them. A helper parameter must not shadow the class. Own argument properties avoid inherited getters; predeclared instance fields are created before the constructor body and avoid inherited setters. Creating an arrow does not execute its body, but the guard does not analyze later calls to the stored arrow. Class fields and argument properties must have noncomputed names and no observable initializer. This is an intentionally conservative diagnostic about syntactic conditions, not a verified correspondence to ECMAScript or a full effect analysis. It does not analyze later calls, exports, module linking or transformed output.

`prototype_guard_test` tests candidates in Node with a poisoned prototype and shows that deleting the argument's own property invokes an inherited getter, while deleting the instance field invokes an inherited setter. With an inherited non-writable data property, a missing argument property reads the inherited value and a write without an own instance field throws in a strict module. The helper tests distinguish storing a callback from invoking it, and reject reassignment, shadowing, unsupported calls and TDZ. Its Node runs are finite behavioral examples; the diagnostic has no Lean proof.

This restricted helper cannot do anything beyond forwarding its argument to the constructor; in particular it does not handle multiple constructors, enum member reads, or writes through potentially inherited setters. The closed module requirement still does not analyze the current downstream Tana bundle or discharge any of its obligations. Extending it requires a real call graph, stable binding and prototype facts, effect-safe argument evaluation, and a proof bridge before it can affect acceptance.

To run it on a local source file: `bb run //devinfra/js/debundle/x/split_proof/translation:prototype_guard -- /path/to/module.js`. It prints a JSON candidate or fallback reason.

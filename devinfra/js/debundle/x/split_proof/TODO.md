- **Unknown code writes every name that escapes anywhere.** A unit that runs unknown code is taken to write every import and every name that escapes anywhere in the bundle, wherever the unit sits: an early start-up unit writes names declared thousands of units later. On the large bundle 1,558 of 9,707 units are such (about 7,800 names each), and 98.5% of its order obligations involve one: `experiments/translation/obligations_report.py --footprints` prints the shares. Writing only what has escaped by the unit's own point would shrink the sets; a name bound later to an object that escaped earlier has to stay in. A prototype passed the golden cases but did not finish on the large bundle in 15 minutes (the current build takes about 3), cause not found; it is not committed. A reviewed vendor table is the other lever ([PLAN.md](experiments/translation/PLAN.md) step 1).
- **One scope resolver.** `Lower.lean` (what a statement mentions) and `Effects.lean` (what it touches) each resolve names, and `frontend.mjs` annotates a third resolution from `eslint-scope` that only `translate` reads. Derive `eager`, `lazy` and `assigns` from the interpreter's run, and compare it with `eslint-scope` the way `experiments/lowering/compare.mjs` compares the scan.
- **Speed of the analysis.** 110 s for 9,707 units of the large bundle, 200 s for `zod` (1,072 units, 103 of them out of budget). Bazel's `lean_binary` runs the checker in Lean's interpreter, about ten times slower than the native build, so a test takes seconds a call. Profile first (`perf`); a `precompileModules` build would help CI.
- **Per-unit reasons in `lower`.** `EFFECTS_WHY=1` prints why units touch the world by first reason, with a few unit numbers each. A second level that prints every unit's reasons and whether it ran out of budget would let a report attribute the out-of-budget units (137 on the large bundle) and a unit's second reason: a unit with two unknown calls stays unknown when a table explains one.
- **Recursion.** A call of a function that is already being run goes on until the depth limit (8), gives up there and counts as a call into the world, so a caller of `isEven(10)` is an effect that writes what the functions reach. Treat a call whose function and arguments are in progress as returning nothing, and iterate to a fixed point.
- **Stack depth.** The interpreter recurses with the syntax. A very deep expression aborts the checker ("Stack overflow") instead of giving a verdict. Run it on a thread with a large stack, or give the recursion a depth limit that gives up the unit. A 20,032-unit library chunk aborts this way somewhere between its units 3,000 and 8,000, also with an unlimited stack; not bisected.

## Reproduce the passing placement

Start with the full editor spec at `368bc9fa`. In a scratch checkout, add the [colors](packages/excalidraw/colors.yaml) and [random](packages/excalidraw/random.yaml) owner files under `devinfra/js/debundle/excalidraw/spec/modules/editor/packages/excalidraw/`. Append the `source_matches` entries from the [groups](packages/excalidraw/groups.yaml) and [constants](packages/excalidraw/constants.yaml) fragments to their respective owners. In the editor import priority insert colors before constants and random before newelement. Leave other owners' relative order unchanged.

For the original replay, the editor placement target took this proposal's `ownership.json` as its `ownership_subset`. Both the selected and full `debundle_resolve_placement` targets must see the same augmented tree. [Resolver export](https://app.buildbuddy.io/invocation/93ee3ca0-03c2-40b8-983f-73500af17096). The source SHA-256 is `fa1cfc7930fe3c0e2b4d95e6cb14ebde21068014cd92db303622509d9a0d455c`. The [selected owner priority](owner_order.json) records the resolver's order. Source ordinals in this note identify observations; the placement input consists of names.

The [deployment target](../../joint.md) exercises the selection in Chromium. The adapter checks the hash and compares each selected owner to the full resolution, then passes the selection and priority to Lean. [Emit, disk recheck and Chromium](https://app.buildbuddy.io/invocation/195eb64c-c6b7-40da-824b-1b3740f4ceb6) passed. In that replay Chromium also checked the five shade indices, returned the first two pinned gray swatches, and called the random factory through the same function object as the editor's public export. The [282-unit trial](https://app.buildbuddy.io/invocation/8540a187-f2c9-4a05-b09a-febfcbab8622) omitted the groups helper. Neither trial used a Rust emit schedule.

## Why the factories stay in the entry

The four module reads in [`_newElementBase`](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/newElement.ts#L77) (1432) have different timing:

- The parameter defaults read [`DEFAULT_ELEMENT_PROPS`](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/constants.ts#L381) (459) **when called**. The defaults object itself reads `COLOR_PALETTE.black`, `COLOR_PALETTE.transparent` and `ROUGHNESS.artist` **during module evaluation**. `ROUGHNESS` (457) is a selected constants record. The palette (367, colors.ts) initializes its arrays by calling `getSpecificColorShades` with `ELEMENTS_PALETTE_SHADE_INDEXES`; the callback indexes the bundled open-color table (304, public). The shades table is from open-color 1.9.1, not a private constant in newElement.ts.
- [`getUpdatedTimestamp`](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/utils.ts#L661) (576) calls `isTestEnv` (581), returning 1 in tests and calling `Date.now()` otherwise. In the bundle the environment check reads the imported environment object's `MODE`. Both utilities move by name from #19760; neither the clock nor the provider runs on behalf of the declaration move.
- [`randomInteger` and `randomId`](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/random.ts) are public. The former reads `random` (1428), initialized with `new Random(Date.now())` using the imported roughjs constructor. The latter reads `isTestEnv`, the counter and nanoid. The seed and ID calls are deferred until a factory needs them.

The ten direct callers in newElement.ts are `newElement`, `newEmbeddableElement`, `newIframeElement`, `newFrameElement`, `newMagicFrameElement`, `newTextElement`, `newFreeDrawElement`, `newLinearElement`, `newArrowElement` and `newImageElement`. The frame factories also use the public element-update helper; the text factory uses public font/measurement helpers and the selected `getTextElementPositionOffsets`. Every caller captures the same private base.

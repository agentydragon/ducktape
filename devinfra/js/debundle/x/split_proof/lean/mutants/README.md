# Callback guard mutation checks

The four test-only `translate` targets compile the production checker with exactly one edit to `Lower.lean`: remove the `unobserved` condition from either the identity-call or closure-factory inference, or omit either deferred references or inert alias references when computing that condition. The Bazel generation step fails if the original guard is not present exactly once. These are deliberately unsound executables; production targets do not depend on them.

`//devinfra/js/debundle/x/split_proof/experiments/translation:callback_mutation_test` runs the same generated callback corpus with seeds 1 and 2026 against the original and each mutant. Each run must complete all direct/plain/object/array-alias and global/local-slot cases. The safe ordering must be accepted and match Node; the unsafe ordering must differ under Node. The original must reject every unsafe ordering, the identity and factory mutants must produce wrong accepts for both direct and alias cases in their respective families, and the deferred-reference and alias-reference mutants must expose their corresponding unsafe cases in both families. An unexpected checker exit, harness error, incomplete corpus, no accepted safe control, or a mutant that survives fails the test rather than counting as detection.

This is a sensitivity check for these particular guard removals and generated examples. It does not establish that the checker is sound or that other mutations would be detected.

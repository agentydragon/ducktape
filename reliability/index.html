Current VM suite: the first executor response never arrived

Both noncached 10:10 failure and 12:03 failure on 30 October assert at agentplane/system_tests/scenarios/central_sampler.py:153 that setup was interrupted. The sampler log gives the earlier error: typed execution initialize receive transport failed … remote effect outcome is unknown; mutation was not replayed: context deadline exceeded. The first Executor.OpenSession response was not received before the intentional long-running sampler command began. agentplane/x/central_sampler/executor_operations.go:155 records the intent, awaits the response, and refuses to replay an unknown remote effect. That guard is correct.

The b9d guest console shows repeated Gateway connect: connection refused at port 9090 until the guest runner service began at 12:06:47; the sampler error followed at 12:07:11. This ordering suggests a startup-sensitive transport interval, but it does not prove dispatch before contact. In current source agentplane/system_tests/central_sampler.py:188 waits for Sandbox Ready; agentplane/sandbox_controller/controller.go:672 and agentplane/sandbox_controller/controller.go:753 require matching Pod UID, Runner boot ID and a renewed live connection Lease. agentplane/sandbox_controller/vm_test.go:204 is the Ready-VM/unconnected-guest negative test. The extra EndpointSlice check confirms routing. The hypothesis that a missing pre-contact gate caused these failures is rejected.

A verified contact observation does not guarantee a subsequent first executor response. VM fixtures allow 120 s for initialization (agentplane/system_tests/k3s/fixture_chart.py:218); the retained sampler log has no exact RPC start timestamp, so handshake duration cannot be independently reconstructed. The passing 504.6 s full suite on another SHA confirms comparable coverage, not same-source recovery. Capture the first-response path after verified contact, and preserve TestExecutorInitializationTimeoutKeepsUnknownOutcome as the negative control.

Legacy VM OOM: a health-triggered exec-server replacement

In the noncached failure, the scripted memory limit caused the guest kernel to kill awk PID 848 at 19:32:49. The Runner boot ID, app-server PID 445 and native Session ID stayed the same, but the follow-up command used a new service cgroup leaf, violating agentplane/system_tests/scenarios/vm_sandbox.py:267. Runner health probes to the Codex exec server failed at 19:33:02, :13 and :23; agentplane/runner/codexexecserver/controller.go:207 restarts the server after three consecutive failures. Guest logs then show codex-exec-server-1 replaced by codex-exec-server-2; agentplane/runner/codexexecserver/server.go:92 and agentplane/runner/supervision/systemd.go:57 place the replacement in a fresh UUID leaf. This is the causal path to the assertion.

Why the original exec server stopped answering remains unknown: aggregate memory pressure, CPU starvation and an exec-server defect remain possible. The observed OOM victim was the intended leaf tool; there is no evidence that the exec server itself was OOM-killed. Capture process/unit and cgroup pressure evidence before changing health thresholds or relaxing the same-leaf contract. This legacy target’s 8/65 tracker record cannot be merged with the new six-scenario suite’s 2/15 record.

Dispatcher cleanup and an already repaired lock path

Two sampled historical dispatcher failures, a789 and f4f6, timed out after 300 s waiting for Ready.reason=Stopped. Diagnostics instead show spec.running=false, operatingMode=Suspended, Ready.reason=Quiescing, a live Lease in quiesce-stage=draining, and a PendingCommand autosuspend blocker. The quiescence predicate was genuinely unmet. Only a789’s retained Runner log repeatedly reports SQLITE_BUSY around journal reopen, ingress and SessionInputs; f4f6 does not prove that same cause.

Both occurred 28 October before #12702 committed at 16:19:18 UTC. Its SQLite busy wait and failed-commit rollback are supported by a controlled physical pair on frozen source: current fix passes and three-hunk rollback fails the same TestFailedCommitReleasesSQLiteLocks check under external-reader contention. With the fix reversed, both append and batch left a writer lock after the reader released it. This proves the repair’s lock-release behavior, not the unknown original lock holder or a post-fix dispatcher recurrence. The legacy test_dispatcher label has been removed. Owning journal diagnosis records the earlier controlled mechanism.

A separate VM invariant: successful setup, missing retained stdout

#12816 tested synthetic merge e49569543d9d77689f4c5f5e143112800a1abcdf in 01de11bd. Setup reached SUCCEEDED and a retained SetupFinished(exit=0); the later executor read its setup-created marker successfully. Nevertheless the retained Session event read contained empty stdout instead of setup-on-executor\n. This is distinct from a first OpenSession response timeout or an RBE VM health failure.

The old standalone target moved, but the same assertion survives at agentplane/system_tests/scenarios/central_sampler.py:424. Current agentplane/runner/scripts/scripts.go joins both pipe readers after process.Wait. agentplane/runner/session/setup.go:21 emits each stdout/stderr chunk as SetupOutput before SetupFinished; Session.Emit journals it before ingress and History publication. This contradicts the simple hypothesis that completion routinely overtakes undrained readers. It does not prove where this historical run lost the output.

Next discriminator: compare the Runner durable journal SetupOutput payload and origin sequence against History ReadSessionEvents at the same cursor. Absence in the journal points to the producer/reader callback; presence points to ingress acknowledgement, History append or the read boundary. Use existing journal/native outputs before adding diagnostics. No direct repair was identified; #12789 added diagnostics before this failure and preserved the assertion. Current recurrence and same-source recovery are not established, so do not merge this older sample into the new-suite first-response rate or weaken retained-output coverage.

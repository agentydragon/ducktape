# Why Does the Best Qwen3 Coder Not Have Reasoning?

Research into an apparent contradiction: reasoning/thinking improves LLM coding
performance in general, but the best Qwen3 variant for agentic coding (Qwen3-Coder)
has no thinking capability.

Researched: 2026-01-27.

## The Contradiction

- Qwen3-Coder-30B-A3B scores ~50-52% on SWE-Bench Verified (agentic coding).
- The base Qwen3-30B-A3B (with thinking toggle) scores ~25%.
- Reasoning models (o1, R1, etc.) generally improved coding benchmarks over their
  non-reasoning counterparts.
- So how is the best coder in the family the one that CAN'T reason?

## 1. Is Qwen3-Coder Actually Better Than Other Qwen3 Variants at Agentic Coding?

**Yes, decisively.**

Independent evaluation by [Nebius](https://nebius.com/blog/posts/openhands-trajectories-with-qwen3-coder-480b)
using the OpenHands agent framework:

| Model                        | SWE-Bench Verified Pass@1 | Thinking          |
| ---------------------------- | ------------------------- | ----------------- |
| Qwen3-Coder-30B-A3B-Instruct | **~50-51.6%**             | Non-thinking only |
| Qwen3-30B-A3B-Instruct-2507  | **~25.7%**                | Hybrid            |
| Qwen3-30B-A3B-Thinking-2507  | Not reported              | Thinking only     |

The Thinking-2507 variant doesn't even have a published SWE-Bench score, suggesting
Qwen themselves don't consider it competitive for agentic coding.

**Critical experiment**: Nebius fine-tuned the base instruct model on 67,074 agent
trajectories generated by Qwen3-Coder-480B. Result: **50.3%** — matching the Coder
variant. This proves the gap is about **training data and specialization**, not
architecture or reasoning capability.

Source: [Nebius SWE-rebench model card](https://huggingface.co/nebius/SWE-rebench-openhands-Qwen3-30B-A3B)

## 2. Does Reasoning/Thinking Improve Agentic Coding in General?

**At frontier scale: sometimes. The picture is surprisingly mixed.**

### Frontier models on SWE-Bench Verified

| Model                        | Type          | SWE-Bench Verified           |
| ---------------------------- | ------------- | ---------------------------- |
| GPT-4o                       | Non-reasoning | ~33%                         |
| o1                           | Reasoning     | ~48.9%                       |
| o3                           | Reasoning     | ~69-72%                      |
| Claude 3.5 Sonnet (upgraded) | Non-reasoning | 49%                          |
| Claude 3.7 Sonnet            | Hybrid        | 62.3-70.3%                   |
| Claude Opus 4                | Hybrid        | **72.5% (without thinking)** |
| Claude Opus 4.1              | Hybrid        | **74.5% (without thinking)** |
| Claude Sonnet 4.5            | Hybrid        | **77.2% (with thinking)**    |

Sources:

- [OpenAI o3 announcement](https://openai.com/index/introducing-o3-and-o4-mini/)
- [Anthropic Claude 4](https://www.anthropic.com/news/claude-4)
- [Anthropic Claude Opus 4.1](https://www.anthropic.com/news/claude-opus-4-1)

**Key finding**: Claude Opus 4 and 4.1 achieved their best SWE-Bench scores
**without extended thinking**. Anthropic explicitly states: "SWE-bench Verified
and Terminal-bench results were achieved without extended thinking."

[Augment Code](https://www.augmentcode.com/blog/1-open-source-agent-on-swe-bench-verified-by-combining-claude-3-7-and-o1)
found that "Sonnet 3.7's thinking mode is not effective within the context of SWE-bench."

### DeepSeek: Reasoning Actually Hurt Agentic Coding

- **DeepSeek-V3**: 42% on SWE-Bench
- **DeepSeek-R1** (reasoning): Lower than V3 on SWE-Bench
- DeepSeek invested in V3 successors (V3.1, V3.2) for agentic tasks, not R1 successors.

Source: [BentoML DeepSeek guide](https://www.bentoml.com/blog/the-complete-guide-to-deepseek-models-from-v3-to-r1-and-beyond)

## 3. At ~30B Scale, Does Reasoning Help?

**Mixed. gpt-oss-20b (with reasoning, high effort) actually beats Qwen3-Coder.**

| Model                                    | Active Params | Reasoning?     | SWE-Bench Verified |
| ---------------------------------------- | ------------- | -------------- | ------------------ |
| **gpt-oss-20b (high reasoning)**         | 3.6B          | Yes            | **60.7%**          |
| Qwen3-Coder-30B-A3B                      | 3B            | No             | ~50-51.6%          |
| DeepSWE-Preview (Qwen3-32B + RL)         | 32B           | Yes (thinking) | 42.2% Pass@1       |
| DeepSWE-Preview (with test-time scaling) | 32B           | Yes            | 59% Pass@16        |
| OpenHands LM 32B                         | 32B           | No             | 37.2%              |
| DeepSeek-R1-Distill-Qwen-32B             | 32B           | Yes            | Not reported       |

Sources:

- [gpt-oss model card (arXiv 2508.10925)](https://arxiv.org/html/2508.10925v1)
- [Together AI DeepSWE blog](https://www.together.ai/blog/deepswe)
- [OpenHands LM announcement](https://openhands.dev/blog/introducing-openhands-lm-32b-a-strong-open-coding-agent-model)

**This complicates the narrative.** gpt-oss-20b has reasoning AND beats Qwen3-Coder
on SWE-Bench (60.7% vs 51.6%), with similar active param count (3.6B vs 3B).
This suggests Qwen3-Coder's advantage was never "no reasoning is better" — it was
"code-specialized Agent RL training is better than generic reasoning." And
gpt-oss-20b apparently got both good agent training AND reasoning.

However, Qwen3-Coder-30B still beats DeepSWE-Preview (32B dense, reasoning) at
Pass@1 despite having 10x fewer active params. So reasoning alone doesn't help —
it's reasoning + agent-specialized training that works.

DeepSeek-R1-Distill-Qwen-32B (the most prominent ~32B pure-reasoning model) doesn't
even have a published SWE-Bench score, suggesting reasoning distillation alone
isn't sufficient for agentic coding.

### SWE-Bench contamination warning

[The SWE-Bench Illusion](https://arxiv.org/html/2506.12286v3) found that models like
o3 achieve up to 76% accuracy on a file-path identification sub-task despite lacking
contextual information — suggesting significant benchmark-specific memorization.

## 5. Why Does The Non-Reasoning Coder Win?

### A. Specialized training matters more than reasoning at ~30B

Qwen3-Coder got:

- 7.5T tokens continued pretraining (70% code)
- Code RL (execution-driven reinforcement learning)
- Agent RL (long-horizon RL on 20,000 parallel simulation environments)

The Nebius experiment proves this is the key: fine-tuning the base model on agent
trajectories (without reasoning) matches the Coder's score.

### B. There is a "reasoning tax" in multi-turn agentic settings

Tencent research found reasoning models consume **~20x more tokens** than conventional
models to reach the same answer. In multi-turn agentic settings (SWE-Bench uses
30-100+ turns), this compounds:

- Thinking tokens consume context window budget
- Each thinking step adds latency to every turn
- At ~30B scale, context window and per-turn budget are precious

Source: [arXiv 2506.08343](https://arxiv.org/html/2506.08343v1)

### C. Reasoning is optimized for single-step depth, not multi-turn breadth

Reasoning models (o1, R1) were trained for deep single-problem reasoning: competitive
programming, math proofs. Agentic coding requires **breadth** — navigating repos,
calling tools, interpreting outputs, iterating across many turns.

One analysis notes: "reasoning models have a tendency to engage in extended circular
reasoning instead of interacting with external tools and information sources."

Source: [Summit Partners analysis](https://www.summitpartners.com/resources/reasoning-models-vs-agentic-ai)

### D. Even frontier models sometimes do better without thinking

Claude Opus 4/4.1 achieved their best SWE-Bench scores without extended thinking.
Anthropic's guidance: "Opus rarely needs thinking — it's already a strong reasoner."
The model has internalized reasoning into its weights.

Same pattern for Qwen3-Coder: Agent RL has internalized the "reasoning" needed for
coding into the weights, without needing explicit thinking tokens.

### E. The real differentiator is Agent RL, not reasoning mode

Both Qwen3-Coder and DeepSWE-Preview achieve their results through RL on real
software engineering environments. The thinking mode is incidental to DeepSWE's
success — what matters is that both were trained on real SWE tasks through trial
and error.

## 6. Does a ~30B Model Exist with Both Reasoning AND Strong Agentic Coding?

**Yes: gpt-oss-20b.** It has reasoning (configurable effort levels), strong tool
calling, and 60.7% SWE-Bench Verified at high reasoning — beating Qwen3-Coder-30B
(51.6%) with similar active param count (3.6B vs 3B). It fits on a single RTX 5090
at ~16 GB.

DeepSWE-Preview (32B) also has reasoning + agentic coding, but needs 10x more active
compute AND 16x sampling to beat Qwen3-Coder.

## Resolution

The original framing ("the best coder has no reasoning, therefore reasoning hurts
agentic coding") was **wrong**. The updated picture:

1. **gpt-oss-20b beats Qwen3-Coder on SWE-Bench AND has reasoning.** So reasoning
   is not inherently bad for agentic coding. The Qwen3 family just didn't combine
   both well.

2. **Code-specialized training (Agent RL) is the biggest factor.** The Nebius
   experiment proves this: fine-tuning the base Qwen3 model on agent trajectories
   matches the Coder's score without reasoning. gpt-oss presumably got equivalent
   agent training.

3. **Reasoning alone doesn't help.** DeepSeek-R1-Distill-Qwen-32B (pure reasoning
   distillation) doesn't even have a published SWE-Bench score. Reasoning without
   agent training is insufficient.

4. **Even at frontier scale**, thinking is sometimes counterproductive for agentic
   tasks. Claude Opus 4/4.1 got their best SWE-Bench scores without extended
   thinking. But this is model-specific, not a universal law.

5. **The Qwen3-Coder vs Qwen3 gap is about training investment, not thinking.**
   Qwen3-Coder got 7.5T code tokens + Agent RL. The base Qwen3 got neither.
   The lack of thinking is a side effect of their divergent post-training pipelines,
   not the cause of the performance difference.

**Bottom line**: The best local model for agentic coding at this scale is likely
**gpt-oss-20b at high reasoning** (60.7% SWE-Bench, reasoning + tools, ~16 GB).
Qwen3-Coder is second (51.6%, no reasoning, ~18 GB FP8). The combination of
reasoning + agent training wins over agent training alone.

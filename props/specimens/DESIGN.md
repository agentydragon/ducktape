# Specimen Test Infrastructure - Design Analysis

## Current Implementation Status

### What We Have

1. **Per-Specimen Test Targets**: Each specimen gets `test_specimen` target generated by `specimen_targets()` macro
2. **Code Tar Generation**: Genrule creates tar.gz with BUILD.bazel.specimen → BUILD.bazel renaming via shell script
3. **Environment Variable Configuration**: Test receives paths via env vars (SPECIMEN_SLUG, SPECIMEN_CODE_TAR, etc.)
4. **Generic Test**: Single `test_specimen.py` instantiated per specimen with testcontainers PostgreSQL
5. **File Renaming**: 287 BUILD.bazel files renamed to BUILD.bazel.specimen to avoid Bazel package conflicts

### Current Issues

1. **Scope Mismatch**: Test fixture trying to use function-scoped monkeypatch in module-scoped fixture
2. **Not Fully Tested**: Haven't verified end-to-end sync + validation yet
3. **Pre-commit Hook Blocking**: Hook prevents changes to specimen code/ directories (including .specimen renames)

## Design Goals vs. Current Implementation

### ✅ Achieved Goals

1. **Per-Specimen Tests**: Each specimen has its own test target (parallel, isolated failures, RBE-compatible)
2. **Generic Test**: Single test file parametrized per specimen
3. **No local = True**: Tests don't require local execution

### ❌ Gaps Against Design Goals

| Goal | Current State | Gap |
|------|---------------|-----|
| **One path for payload generation** | Tests use genrule tar, production sync reads source tree directly | **DUPLICATE PATHS**: Test path ≠ production path |
| **One synchronization path** | Test calls `sync_all()`, but specimen extraction logic is test-specific | **PARTIAL DUPLICATION**: Tar extraction in test, direct read in prod |
| **Starlark file renaming** | Uses shell script with heredoc, `cp`, `tar` | **SHELLS OUT**: Should use Starlark glob + rename instead |
| **DRY Starlark** | Logic spread across genrule shell, test Python, sync Python | **SCATTERED**: No single source of truth |
| **Manifest generation** | Manifests committed to repo | **NOT GENERATED**: Manifest still manual |
| **Covers external repos** | Only handles in-repo specimens | **MISSING**: No git_repository integration for crush |
| **Single payload concept** | Separate handling for code tar vs issues glob | **FRAGMENTED**: Code and issues not unified |

## Proposed Architecture

### Core Concept: Unified Specimen Payload

A "specimen payload" is a single conceptual object containing:
- Code (with BUILD.bazel files restored)
- Issues (YAML files)
- Minimal metadata (generated manifest)

This payload is:
1. Generated once in Starlark
2. Used by both tests AND production sync
3. Defined for both local and external specimens

### Implementation Proposal

#### 1. Starlark-Based File Renaming (No Shell-Out)

```python
def specimen_targets(name, slug):
    """Generate specimen payload and test targets."""

    # Collect code files with Starlark (no shell)
    code_files = native.glob(["code/**/*"], exclude=["code/**/.git/**"])

    # Build rename mapping in Starlark
    rename_pairs = []
    for f in code_files:
        if f.endswith(".specimen"):
            # Target name: strip .specimen
            target = f[:-len(".specimen")]
            rename_pairs.append((f, target))
        else:
            rename_pairs.append((f, f))

    # Use pkg_tar with renames dict (avoiding shell tar)
    pkg_tar(
        name = name + "_code_tar",
        srcs = code_files,
        renames = {src: dst for src, dst in rename_pairs},
        package_dir = "code",
        out = name + "_code.tar.gz",
    )

    # Generate manifest from metadata (not committed)
    _generate_manifest(
        name = name + "_manifest",
        slug = slug,
        # Other metadata from macro params, not from checked-in file
    )

    # Compile all issues into single YAML blob (using yq)
    _compile_issues(
        name = name + "_issues_blob",
        srcs = native.glob(["issues/**/*.yaml"]),
    )

    # Create unified payload target
    native.filegroup(
        name = name + "_payload",
        srcs = [
            ":" + name + "_code_tar",
            ":" + name + "_manifest",
            ":" + name + "_issues_blob",
        ],
    )
```

## Key Changes Needed

### High Priority

1. **Unify sync path**: Make `props/db/sync` use same payload format as tests
   - Both should use `SpecimenPayload` abstraction
   - Single `sync_to_db()` implementation
   - Remove duplication between test tar extraction and prod source reading

2. **Move to Starlark renaming**: Replace genrule shell script with pkg_tar + renames dict
   - Avoids shell-out
   - More declarative
   - Better Bazel integration

3. **Generate manifests**: Stop committing manifest.yaml, generate from macro params
   - Trim schema: remove bundle metadata, exclusion patterns
   - Move remaining fields to BUILD.bazel specimen_targets() calls

### Medium Priority

4. **Compile issues blob**: Use yq to merge issue YAMLs
   - Saves rglob during sync
   - Single file easier to handle
   - Can still preserve per-issue structure internally

5. **External specimen support**: Test git_repository integration with crush
   - Proves multi-repo architecture works
   - Validates that sync path is truly unified

### Low Priority

6. **Pre-commit hook update**: Allow .specimen file changes
   - Current hook blocks renaming
   - Need to distinguish "changing specimen logic" from "changing build metadata"
